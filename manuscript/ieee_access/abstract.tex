A compiler that runs inside a fixed memory budget needs a symbol table whose size is fixed in advance, whose behavior at the limit is defined, and whose index work per call can be bounded on hostile source text. We present STRATA, a scoped symbol table that keeps an open-addressing index, packed identifier records and an undo stack in one caller-supplied buffer; a call that does not fit is refused and leaves the buffer unchanged. For every open-addressing rule that never moves a key, removing the newest key by clearing its cell restores the previous index exactly, and for linear probing last-in-first-out order is the only deletion order safe for every table. In an ideal random-hash model this gives the exact probability that a probe limit refuses the next fresh name; for a table of 65\,536 slots at load three quarters a refusal probability of one in a million per request needs 258 probes, against 455 for a Chernoff-type tail bound. The law agrees with the implementation in 3.7 million trials at up to 16\,384 index slots, and with the default hash on real identifiers, and we bound the refusal-filtered process, for insertion-only schedules, that the law does not describe exactly. On events logged by a C compiler for eight projects STRATA gave no wrong answer and needed a fixed buffer 16.4 to 17.9 percent smaller than a conventional single-buffer table that stores a hash word, but only 5.3 to 9.0 percent smaller than one that does not, a saving that comes from name packing. In repeated timing sessions on a library version that executes 6 to 8 percent more instructions than the final one, it was slower than the table with a stored hash word by 8 to 20 percent and than the one without by up to 13 percent. Bounded mode limits index slot examinations per declaration and lookup, not scope exit or the default-mode rebuild. Identifiers that collide for every seed slow the unkeyed table 300-fold; a keyed hash removes this effect for that collision family, and keeping honest names from being refused next to such names needs a fresh key per table, whose derivation is left to the caller.
