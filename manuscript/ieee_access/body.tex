\section{Introduction}
\label{sec:introduction}
\PARstart{A}{scoped} symbol table maps program identifiers to their associated declarations and discards declarations belonging to an inner scope once that block terminates~\cite{aho2006}. As one of the foundational data structures in compiler construction~\cite{graham1979}, its design on unconstrained workstations is widely considered an established problem: pairing an off-the-shelf hash map with an auxiliary undo stack typically suffices~\cite{appel1998}. However, this conventional approach proves inadequate when the compiler or runtime system must execute within strictly constrained execution environments. Language front ends embedded on microcontrollers, inside secure boot loaders, or within static analysis tools operating under rigid memory quotas impose three fundamental requirements that traditional designs do not satisfy:

\emph{Bounded memory.} The table must reside entirely within a predetermined memory region allocated prior to translation, avoiding dynamic memory allocators whose heap fragmentation and non-deterministic failure modes lie outside the compiler's control.

\emph{Defined behavior at the bound.} When an insertion exceeds available storage, the table must report the failure cleanly while preserving total internal consistency. A partially mutated table risks turning an out-of-memory condition into silent, catastrophic compilation errors.

\emph{Bounded work on untrusted input.} When processing third-party or untrusted source text, the operational cost of individual table accesses must not be vulnerable to pathological identifier selections. Hash tables are well-known targets of algorithmic complexity attacks~\cite{crosby2003}, and naive seed randomization on standard non-cryptographic hashes does not prevent systematic multicollisions~\cite{aumasson2012}.

The scoped symbol tables we inspected, the textbook undo-stack scheme, LLVM's \code{ScopedHashTable} and the Tiny C Compiler's symbol stacks~\cite{appel1998,llvmsht,tcc}, obtain memory from a general allocator, treat an allocation failure as fatal or leave it unspecified rather than returning a refusal with the table unchanged, and use unkeyed hashes. On the analytical side, while the theory of open addressing extensively covers insertions and deletions in arbitrary order~\cite{knuth3,bender2021,fkk2024}, the structured last-in-first-out (LIFO) deletion sequence inherent to lexical scoping has not been analyzed as a distinct structural regime, and operational probe limits are typically chosen via tail bounds of uncharacterized looseness.

In this article, we investigate the concrete costs of simultaneously satisfying all three requirements and provide principled guidelines for configuring such tables. We present \st, a scoped symbol table encapsulated within a single caller-supplied buffer of 32-bit words. While its underlying algorithm employs the classical combination of a single hash index, packed records, and an undo stack for scope exit~\cite{appel1998}, our primary contributions lie in the unified single-buffer architecture, the formal proofs governing its structural and probabilistic invariants, and an extensive empirical evaluation:

\begin{enumerate}
\item \textbf{A single-buffer scoped symbol table with all-or-nothing refusal.} Hash index slots, interned identifier records with innermost bindings, hidden declarations, and scope markers share a single caller-supplied buffer. Any operation that exceeds available capacity returns an explicit status code and leaves the underlying buffer state byte-for-byte unchanged (Sections~\ref{sec:design} and~\ref{sec:verification}).
\item \textbf{Exact undo and its converse.} We prove that for any non-reordering open-addressing scheme, removing the most recently inserted key simply by clearing its slot exactly reconstructs the preceding index state, ensuring that the index is always identical to an insertion-only table of live names. For any given table state, the safe deletion orders correspond precisely to the linear extensions of a dependency relation; furthermore, for linear probing, LIFO order is the only deletion order universally safe across all table states (Section~\ref{sec:undo}).
\item \textbf{An exact refusal law for bounded probing.} For a static index under probe limit $L$, we derive the exact finite-size probability that an honest identifier is refused under an ideal hashing model, validate this distribution empirically against the implementation, and establish formal bounds for the refusal-filtered process. We also demonstrate that standard Chernoff-type bounds are loose by a factor growing as $L^{3/2}$ (Section~\ref{sec:bounded}).
\item \textbf{Empirical decomposition on compiler workloads.} Replaying trace events captured from C compilers across eight open-source benchmarks, we isolate the footprint gains of single-buffer operation from the compact layout itself. An exact space ledger shows that the saving comes from name packing and the omitted hash word, not from identifier interning; we measure the stronger baseline without a stored hash, and report that \st\ is slower than both conventional single-buffer tables (Section~\ref{sec:results}).
\item \textbf{Collision attacks, defenses, and key lifetimes.} We construct universal multicolliding C identifiers against the default hash mixer, quantify the resulting algorithmic slowdown alongside the overhead of keyed hashing, and establish the operational conditions under which fresh keyed instances defend against oblivious adversaries (Sections~\ref{sec:keyed} and~\ref{sec:flood}).
\end{enumerate}

We do not claim a new hashing scheme, a faster symbol table, or a result on hardware. \st\ is slower than a conventional single-buffer table; the refusal probability is classical as a quantity (the tail of the unsuccessful-search cost) and is credited as such, and what is new is its explicit finite-size sum, its validation against an implementation, the bounds for the refusal-filtered process and its use as a design rule; the collision construction applies a published technique~\cite{aumasson2012}; and the microcontroller is emulated. Section~\ref{sec:limits} explicitly details the boundary conditions and experimental limitations of our findings.

The remainder of this article is structured as follows. Section~\ref{sec:related} reviews related work, and Section~\ref{sec:problem} formalizes the problem and threat model. Section~\ref{sec:design} presents the architecture of \st, Section~\ref{sec:undo} establishes the exact undo theorem, and Section~\ref{sec:bounded} derives the refusal law under bounded probing. Section~\ref{sec:verification} details our verification methodology, Sections~\ref{sec:setup} and~\ref{sec:results} report the experimental setup and results, and Section~\ref{sec:tool} introduces the interactive visualization tool. Sections~\ref{sec:discussion} through~\ref{sec:conclusion} provide broader discussion, discuss limitations, and conclude.

\section{Related Work}
\label{sec:related}

\subsection{Scoped Symbol Tables}
Graham \emph{et al.}~\cite{graham1979} described hashed symbol tables for programming languages with explicit block structure. The architectural baseline adopted here follows Appel's classic formulation for block-structured languages~\cite{appel1998}: a single central hash table maps each identifier to its innermost binding, an auxiliary stack tracks the bindings created within each scope, and scope exits pop the stack to restore shadowed declarations. This organization ensures that lookup latency remains independent of lexical nesting depth, in contrast to traditional cascades of per-scope maps~\cite{aho2006}. In modern production software, LLVM's \code{ScopedHashTable}~\cite{llvmsht} offers a reusable implementation relying on heap-allocated nodes; lcc~\cite{fraserhanson1995} links separate table structures per scope level, and the Tiny C Compiler~\cite{tcc} maintains symbol stacks popped upon scope exit. In the versions we inspected, all of them allocate per symbol or per node; TinyCC exits the process when an allocation fails and LLVM's allocators report a fatal error by default, which is defined behavior but not a refusal after which the table can be used; and we found no documented bound on the work of a call. Region-based allocation~\cite{hanson1990} eliminates much of the general allocator overhead in compiler implementations; a chained table whose entries reside within a contiguous stack-like arena represents its natural single-buffer manifestation and serves as our primary baseline. In embedded execution environments, runtimes such as MicroPython intern identifiers into shared string pools~\cite{micropython}, addressing identifier duplication but leaving lexical scoping and allocation failure handling unaddressed.

\subsection{Deletion in Open Addressing}
Evicting a key from an open-addressing table using linear probing typically necessitates sentinel tombstones or backward-shift displacements~\cite{knuth3,jimenez2018}, and the specific deletion strategy profoundly influences long-term cluster formation~\cite{bender2021}. Sanders~\cite{sanders2018} established the exact conditions governing when an evicted entry requires a tombstone. Alternative schemes such as Robin Hood hashing~\cite{celis1985} (employed in the predecessor to this work~\cite{metis}), cuckoo hashing~\cite{pagh2004}, and hopscotch hashing~\cite{herlihy2008} actively relocate keys during insertion and deletion. While the fact that the most recently inserted key in linear probing can be removed simply by clearing its slot is a natural consequence of greedy probing (and occasionally leveraged in backtracking code), we formalize this property for all non-reordering schemes, characterize all safe deletion orders, and leverage this structural invariance for exact finite-size analysis. This behavior is conceptually related to, yet strictly weaker than, strong history independence~\cite{naor2001,blelloch2007}: here, buffer layout is a deterministic function of the live identifiers and their insertion sequence.

\subsection{Analysis of Open Addressing}
Under an ideal random hashing model, Knuth formulated the classical exact analysis of insertion-only linear probing~\cite{knuth3}. The distribution of unsuccessful search costs—whose tail corresponds directly to the refusal probability analyzed in this work—has been characterized through exact generating functions and Poisson approximations~\cite{fpv1998,janson2001,janson2016}, while the displacement distribution of Robin Hood hashing~\cite{janson2005,viola2005} reappears in Section~\ref{sec:undo} as an orphan key distribution. Recent theoretical advances have characterized optimal probe complexities for non-reordering open addressing~\cite{fkk2024} and the performance of dynamic workloads~\cite{tinypointers2025}. Alharbi, Banderier, and Bouillaguet~\cite{abb2026} analyzed bounded linear probing under a model where keys exceeding a probe threshold are discarded and redrawn; in contrast, our system models clean refusal without mutation under LIFO scope rollback, representing a fundamentally distinct stochastic process. Pagh \emph{et al.}~\cite{pagh2007} and Thorup~\cite{thorup2015} provided complementary analyses of linear probing under limited hash independence.

\subsection{Algorithmic Complexity Attacks}
Crosby and Wallach~\cite{crosby2003} demonstrated that an attacker capable of generating hash collisions can degrade hash table performance from constant time to quadratic worst-case list traversals. Aumasson and Bernstein~\cite{aumasson2012} showed that non-cryptographic hashes including MurmurHash2 and MurmurHash3 admit universal multicollisions that hold across all seed values, and proposed SipHash as a secure alternative; an accompanying presentation~\cite{aumassonslides} detailed the specific construction for MurmurHash3. HalfSipHash configured with one compression and three finalization rounds is recognized in the Linux kernel as an efficient mitigation against hash-table flooding~\cite{linuxsiphash}. Adaptive attacks exploiting timing discrepancies have long been documented~\cite{lipton1993,naor2015}. Production compilers handling trusted inputs commonly prioritize throughput over security: for example, the internal hash table of the Rust compiler is deliberately unkeyed~\cite{rustchash}. Here, we explore the adversarial scenario, measuring both attack degradation and defensive countermeasures within a scoped symbol table.

\emph{What is known, what is new, and why the combination matters.} Every ingredient of \st\ is known: the hashed table with an undo stack~\cite{appel1998}, linear probing~\cite{knuth3}, region allocation~\cite{hanson1990}, packed names, fingerprints, keyed hashing~\cite{aumasson2012} and the distribution of the unsuccessful-search cost~\cite{knuth3,janson2016}. We do not claim any of them. The contribution is that, to our knowledge and within the limited literature search stated in Section~\ref{sec:limits}, they have not been put together so that each one makes another one usable, and that this yields guarantees none of them gives alone. Removing a scope's names by clearing their cells (Theorem~\ref{thm:undo}) is what allows the classical analysis of an \emph{insertion-only} table to describe a table that is being edited all the time, and that is what turns a probe limit from a guess into a computable design value (Section~\ref{sec:law}); a probe limit without that analysis would be set by a loose bound, as it was in an earlier version of this study. The probe limit together with a keyed hash bounds the work of a call on hostile input, and the refusal law prices what that bound costs honest input. \section{Problem Formulation}
\label{sec:problem}

\subsection{Operations and Semantics}
A scoped symbol table manages identifier bindings across a stack of lexical scopes, initialized with a single outermost global scope, supporting four core operations:
\begin{itemize}
\item \code{enter}: push a new innermost lexical scope.
\item \code{exit}: terminate the current innermost scope, invalidating all declarations introduced within it; disallowed at the global scope.
\item \code{declare}$(x, v)$: bind identifier $x$ to semantic value $v$ in the innermost scope. If $x$ is already declared at the current depth, its binding is overwritten; otherwise, a new declaration is introduced, shadowing any identically named declarations in outer scopes.
\item \code{resolve}$(x)$: retrieve the value associated with the innermost visible declaration of $x$, or report that no active binding exists.
\end{itemize}
An identifier is a non-empty byte sequence of at most 255 bytes. A semantic value comprises a 32-bit integer coupled with an 8-bit type tag. We denote by $d$ the number of active declarations, $n \le d$ the count of unique identifiers among them, $s$ the number of open local scopes, and $w(x)$ the storage size of identifier $x$ in 32-bit words.

\subsection{Requirements}
\label{sec:requirements}
\begin{itemize}
\item[R1] \textbf{Fixed storage.} All table structures must reside within a single caller-allocated buffer of $C$ 32-bit words, executing entirely without calls to dynamic memory allocators.
\item[R2] \textbf{All-or-nothing refusal.} Operations must execute atomically: any request that cannot be accommodated returns an explicit status code and leaves the complete internal state unmodified.
\item[R3] \textbf{Correct scoping.} Every invocation of \code{resolve} returns the exact declaration dictated by lexical scoping semantics across all successfully committed operations.
\item[R4] \textbf{Bounded index work per call.} In static-index (bounded) mode, an operational parameter $L$, independent of active declarations $d$ or identifier names, strictly bounds the maximum number of index slots inspected during \code{declare} and \code{resolve}. This bound governs slot examinations rather than aggregate execution latency: \code{exit} inherently scales with the number of declarations in the closing scope, and default-mode table resizing scales with $n$. Section~\ref{sec:bounded} maps $L$ to aggregate operation bounds.
\item[R5] \textbf{Rare, quantified refusal of honest input.} Under R4, the probability that a benign declaration is refused when buffer capacity remains available must be mathematically characterized and negligible.
\end{itemize}
Requirements R1 through R3 are satisfied by \st\ in default mode as well as our arena baseline. Requirements R4 and R5 are guaranteed by bounded mode, with R5 evaluated under the analytical model of Section~\ref{sec:bounded}.

\subsection{Threat Model}
\label{sec:threat}
We assume an adversary who supplies the source text, exercising full control over identifier selection and operation ordering. The adversary possesses complete knowledge of the table implementation and hash function algorithms, but cannot predict a private 64-bit seed initialized by the host device from an unpredictable entropy source. We consider two threat models: an \emph{oblivious} adversary, who fixes all identifiers prior to key generation, and an \emph{adaptive} adversary, who observes runtime indicators (such as refusal occurrences or timing variations) to guide subsequent identifier choices within a single table session. The adversary aims to degrade lookup throughput into worst-case linear scans or induce spurious refusals of legitimate identifiers under bounded probing. Memory-safety vulnerabilities and hardware side channels are considered orthogonal; Section~\ref{sec:keyed} examines the consequences of direct probe-length disclosure. Finally, exhausting buffer memory through a sheer volume of distinct identifiers represents ordinary capacity consumption rather than an algorithmic flaw; requirement R2 ensures that the table remains robust and queryable following exhaustion.

\section{Design of STRATA}
\label{sec:design}

\subsection{Architecture and Layout}
\strfigwide[0.92\textwidth]{figures/fig_arch.pdf}{Architecture. The compiler front end issues four calls to a \st\ table that keeps its open-addressing index, packed identifier records and undo stack in one fixed buffer; the analysis of Sections~\ref{sec:undo} and~\ref{sec:bounded} turns the model of the index into design rules for the probe limit, the buffer size and the key policy.}{fig:arch}
\strfig{figures/fig_layout.pdf}{Layout of the buffer and of the three kinds of undo entries. The index and the identifier records grow from the start of the buffer, the undo stack from its end; the free space between them is shared.}{fig:layout}

Fig.~\ref{fig:arch} illustrates the system architecture, and Fig.~\ref{fig:layout} depicts the internal buffer layout. All internal state resides within a contiguous array of 32-bit words. The \emph{hash index} occupies the first $m$ words ($m$ being a power of two). An empty slot is represented by zero; an occupied slot stores an 8-bit hash fingerprint alongside a 24-bit relative word reference to an identifier record. Collisions are resolved via linear probing, maintaining a maximum load factor of $\alpha \le 0.75$.

The \emph{identifier records} are placed directly following the hash index, growing upward towards the end of the buffer with exactly one record allocated per distinct visible identifier. Each record stores the semantic value of the identifier's \emph{innermost} visible binding, a 32-bit metadata word (encoding the record length in words, a raw-storage flag, a type tag, and lexical scope depth), followed by the encoded name words. Consequently, lookup terminates immediately upon matching the identifier record, with latency independent of how deeply shadowed the identifier may be. Identifiers adhering to standard C identifier syntax (alphanumeric characters and underscores) are compactly encoded at five characters per 32-bit word using 6-bit codes ranging from 1 to 63 (preserving zero as a sentinel). A lookup packs the query once and compares it with stored names word by word. Arbitrary identifiers containing extended byte values are stored as raw bytes padded to 4-byte boundaries. Table~\ref{tab:encoding} details the complete bit-level layout.

Packed identifiers avoid the need for separate length fields: because character codes are strictly positive, zero padding in the terminal word cannot be misconstrued as valid characters, and identifiers of different lengths naturally diverge in word counts or terminal padding bits. Raw strings are copied byte by byte with zero padding, storing the length modulo 4 in the metadata word to preserve distinction between strings containing trailing nulls; the raw-format flag distinguishes raw from packed encodings of identical word length. Words are stored in native host byte order; consequently, serialized buffers are not binary-portable across different endianness platforms, and keyed hashing was validated on little-endian architectures. Identifier references are 24 bits wide with reference zero reserved ($\mathit{itop}$ begins at 1), capping the maximum addressable buffer size at $2^{24}-1$ words (67\,108\,860 bytes, approximately 64\,MiB). Because the identifier stack cannot exceed the 24-bit addressing boundary before exhausting physical buffer capacity, the explicit reference check in Algorithm~\ref{alg:declare} acts as a defensive safeguard that remained unreached across all empirical benchmarks. Callers are required to provide a 4-byte aligned memory region as part of the library contract.

The \emph{undo stack} grows downward from the high end of the buffer. Declaring a previously unseen identifier pushes a single word recording the allocated index slot. Declaring an identifier that shadows an outer binding pushes three words: the record reference alongside the displaced value, type tag, and scope depth. Entering a scope pushes a two-word marker capturing the current top of the identifier stack and the location of the previous scope marker. For an index of $m$ slots, total active buffer consumption is bounded by
\begin{equation}
M = m + 1 + \sum_{x} \bigl(2 + w(x)\bigr) + n + 3\,(d - n) + 2\,s
\label{eq:memory}
\end{equation}
words, where the summation spans the $n$ distinct visible identifiers and the additive constant accounts for reserved reference zero. In comparison, the conventional arena baseline (Section~\ref{sec:baselines}) stores for each declaration a bucket link, full hash word, semantic value, combined length-depth word, and the unpacked identifier bytes.

\subsection{Declaration and Lookup}
Algorithm~\ref{alg:declare} outlines the declaration pipeline. Following a strict \emph{validate-search-reserve-write} lifecycle, the initial search phase is entirely read-only. The only operation capable of mutating buffer layout prior to the final refusal point is \textsc{Ensure} (Algorithm~\ref{alg:ensure}), which guarantees atomic completion without intermediate state corruption. An unsuccessful search naturally halts at the first unoccupied slot encountered along the identifier's probe sequence—identically where linear probing inserts fresh keys. This slot index is cached and reused, ensuring that successful declarations traverse the probe path exactly once. If \textsc{Ensure} triggers an index resize (which is disabled in bounded mode), the cached slot index is invalidated and a fresh insertion probe is conducted.

\begin{algorithm}[t!]
\caption{\textsc{Declare}$(x, v)$}
\label{alg:declare}
\begin{algorithmic}[1]
\REQUIRE name $x$ (1 to 255 bytes), value and type $v$; current depth $\delta$; probe limit $L$ (bounded mode) or $L=\infty$
\ENSURE a status; the state is unchanged unless the status is \code{ok} or \code{redeclared}
\IF{table invalid} \RETURN \code{no-memory} \ENDIF
\STATE $K \leftarrow \textsc{MakeKey}(x)$; \textbf{if} $|x|=0$ \textbf{return} \code{empty-name}; \textbf{if} $|x|>255$ \textbf{return} \code{name-too-long}
\STATE $(r, e) \leftarrow \textsc{Find}(K, L)$ \hfill\COMMENT{read-only; record or first empty slot within $L$ probes}
\IF{$r \neq \code{nil}$ \AND $\mathit{depth}(r) = \delta$}
  \STATE overwrite value and type of $r$; \RETURN \code{redeclared}
\ELSIF{$r \neq \code{nil}$}
  \IF{\NOT \textsc{Ensure}$(3, 0)$} \RETURN \code{no-memory} \ENDIF
  \STATE push $(r\,|\,\text{shadow bit}, \mathit{value}(r), \mathit{type}(r), \mathit{depth}(r))$; overwrite value, type, depth of $r$; \RETURN \code{ok}
\ENDIF
\IF{$\mathit{itop} + 2 + |K| > 2^{24}-1$} \RETURN \code{no-memory} \ENDIF
\IF{\NOT \textsc{Ensure}$(3 + |K|, 1)$} \RETURN \code{no-memory} \ENDIF \hfill\COMMENT{may grow; all-or-nothing}
\IF{$L<\infty$ \AND $e = \code{nil}$} \RETURN \code{probe-limit} \ENDIF \hfill\COMMENT{last refusal point}
\STATE append the record for $x$ with $v$ and $\delta$; store reference and fingerprint in $e$ (or reinsert, if the index was rebuilt)
\STATE push the slot on the undo stack; \RETURN \code{ok}
\end{algorithmic}
\end{algorithm}

\emph{Status precedence.} Error conditions are evaluated strictly in the order shown in Algorithm~\ref{alg:declare}: table validity, empty string, excessive length, same-scope redeclaration (which requires no allocation), memory exhaustion (\code{no-memory}, covering reference overflow, load factor violation, or buffer deficit), and finally probe limit exhaustion (\code{probe-limit}). An identifier that is both overly long and exceeds available memory reports \code{name-too-long}; an operation that exceeds both memory capacity and the probe limit reports \code{no-memory}. Scope entry verifies validity, maximum nesting depth (\code{too-deep}), and memory; scope exit checks validity and non-zero depth (\code{no-scope}). Search strings are normalized into a stack-resident buffer (268 bytes: 64 name words and three header words) before performing mutations, ensuring safe operation even if the input string references data within the table's own buffer prior to relocation. Capacity reservations are evaluated using 64-bit integer arithmetic, with architectural boundaries (24-bit references, 255-byte length, 64-word names, and $16\,383$ scope levels) verified prior to writing.

Identifier lookup packages and hashes the query name, probing sequentially from its home slot until finding a slot matching the fingerprint, metadata, and packed words, encountering an empty slot, or reaching the probe threshold $L$. Hash fingerprints function purely as early rejection filters; every candidate match is verified by comparing identifier words directly.

\subsection{Scope Entry and Exit Without Tombstones}
\label{sec:exit}
\strfigwide[0.8\textwidth]{figures/fig_flow.pdf}{Flow of a declaration and of a scope exit. A declaration is refused, with the table unchanged, when no empty slot is found within $L$ probes or when the record and its undo entry do not fit; a scope exit pops the undo entries in reverse order.}{fig:flow}
Entering a scope reserves two words and pushes a scope marker, failing only upon nesting overflow or buffer exhaustion. Exiting a scope unwinds the undo stack down to the active scope marker in reverse chronological order (Algorithm~\ref{alg:scope}, Fig.~\ref{fig:flow}). Three-word shadowing entries reinstate the overwritten value, type, and depth fields. Single-word new-name entries directly clear their corresponding index slot. The identifier stack top is then restored from the marker, instantly reclaiming records allocated within that scope.

Simply clearing the slot is sound because of the strict LIFO removal order: being the most recently inserted key in the index, the evicted key cannot lie on the active probe path of any previously inserted live key. Section~\ref{sec:undo} proves this invariance for all non-reordering schemes and demonstrates that no alternative deletion order guarantees this property universally. Consequently, scopes close without writing tombstones or performing backward key shifts. Scope exit operations cannot fail due to memory exhaustion: they strictly deallocate storage and, in default growable mode, may optionally release heap blocks to the system allocator without compromising table validity if the request is declined.

\begin{algorithm}[t!]
\caption{\textsc{Enter} and \textsc{Exit}}
\label{alg:scope}
\begin{algorithmic}[1]
\STATE \textbf{procedure} \textsc{Enter}
\IF{table invalid} \RETURN \code{no-memory} \ENDIF
\IF{$\delta \ge 16\,383$} \RETURN \code{too-deep} \ENDIF
\IF{\NOT \textsc{Ensure}$(2, 0)$} \RETURN \code{no-memory} \ENDIF \hfill\COMMENT{last refusal point}
\STATE push mark $(\mathit{itop}, \mathit{mark})$; $\mathit{mark} \leftarrow$ its position; $\delta \leftarrow \delta + 1$; \RETURN \code{ok}
\STATE \textbf{procedure} \textsc{Exit}
\IF{table invalid} \RETURN \code{no-memory} \ENDIF
\IF{$\mathit{mark} = 0$} \RETURN \code{no-scope} \ENDIF \hfill\COMMENT{last refusal point}
\WHILE{undo stack above $\mathit{mark}$}
  \STATE $\epsilon \leftarrow$ top entry
  \IF{$\epsilon$ is a shadow entry}
    \STATE restore value, type, depth of its record; pop 3 words
  \ELSE
    \STATE empty the index slot $\epsilon$; pop 1 word
  \ENDIF
\ENDWHILE
\STATE $(\mathit{itop}, \mathit{mark}) \leftarrow$ saved fields of the mark; pop 2 words; $\delta \leftarrow \delta - 1$; \RETURN \code{ok}
\end{algorithmic}
\end{algorithm}

\subsection{All-or-Nothing Refusal}
Every table operation validates arguments, verifies capacity reservations, and only mutates memory once success is guaranteed. In fixed-buffer mode, reservations reduce to straightforward pointer and counter arithmetic. When dynamic resizing is enabled, \textsc{Ensure} (Algorithm~\ref{alg:ensure}) secures the expanded memory block before initiating any data migration, ensuring that allocation failure aborts cleanly prior to state alteration. Once capacity is reserved, subsequent writes cannot fail. As a result, every refusal condition—insufficient buffer memory, nesting depth exceeding $16\,383$, empty or over-length names, or probe limit exhaustion—preserves the existing state completely unchanged (verified across all boundary conditions in Section~\ref{sec:verification}).

\subsection{Growing the Index}
\label{sec:rebuild}
In default mode, the index doubles in size whenever inserting a key would violate the load factor threshold. Identifier records are migrated upward as a contiguous memory block, enabled by relative offset referencing, and the index is reconstructed by reinserting active identifiers in chronological order (oldest first), preserving the LIFO invariants required by Section~\ref{sec:exit}. Because one-word undo entries store absolute index slot positions that shift during relocation, each identifier record and its corresponding undo entry temporarily swap word values prior to reindexing, restoring them during reinsertion. This eliminates secondary search passes and avoids auxiliary scratch allocations. In default mode, an operation triggering an index rebuild exhibits $O(n)$ latency; in bounded mode, static index sizing completely eliminates dynamic rebuilds.

\begin{algorithm}[t!]
\caption{\textsc{Ensure}$(w, a)$: room for $w$ stack words and $a$ new index entries}
\label{alg:ensure}
\begin{algorithmic}[1]
\IF{static index (bounded mode)} \RETURN $(\,\text{names}+a)\cdot 4 \le \text{slots}\cdot\lambda \;\AND\; \text{free words} \ge w$ \ENDIF \hfill\COMMENT{pure comparison}
\STATE $m' \leftarrow m$; \textbf{while} $(\text{names}+a)\cdot4 > m'\lambda$ \textbf{do} $m' \leftarrow 2m'$ \hfill\COMMENT{$\lambda = 3$ (or 2, sparse)}
\IF{$m' = m$ \AND free words $\ge w$} \RETURN true \ENDIF
\STATE $\mathit{need} \leftarrow m' + \mathit{itop} + \mathit{undo} + w$
\IF{$\mathit{need} \le C$} \RETURN \textsc{Relocate}$(C, m')$ \ENDIF \hfill\COMMENT{index grows inside the buffer}
\IF{fixed buffer} \RETURN false \ENDIF
\STATE $C' \leftarrow \min(1.5\,C \text{ or } \mathit{need},\ \text{limits})$; \textbf{if} $C' < \mathit{need}$ \textbf{return} false
\RETURN \textsc{Relocate}$(C', m')$
\STATE \textbf{procedure} \textsc{Relocate}$(C', m')$ \hfill\COMMENT{the only mutating step}
\STATE obtain the new block (the single failure point; on failure return false); stash undo entries; move undo stack, then records; rebuild the index oldest first; update $C$, $m$, undo references; return true
\end{algorithmic}
\end{algorithm}

\section{Exact Undo and Safe Deletion Orders}
\label{sec:undo}
\strfigwide[0.82\textwidth]{figures/fig_undo.pdf}{Exact undo. Pushing $x$ writes one empty cell; popping $x$ clears it, and the table is identical in every cell to the table before the push.}{fig:undo}

Model the index as a ring of $m$ cells. A rule is \emph{non-reordering} if a key never moves after it is placed and the cell chosen for an insertion depends only on the set of occupied cells and on the key's own probe sequence; this covers linear, quadratic and double hashing and uniform probing, and excludes cuckoo, hopscotch and Robin Hood hashing. The operations are \emph{push}, which inserts a name that is not live, and \emph{pop}, which removes the most recently pushed live name by clearing its cell; a refused push changes nothing. In \st\ the pushes are the \emph{first} declarations of names, since a shadowing declaration needs no index slot. For a sequence $a=(a_1,\ldots,a_t)$ of distinct names, $\Ins(a)$ is the table obtained by inserting them in this order into the empty table.

\begin{theorem}[Exact undo]
\label{thm:undo}
For every non-reordering rule, after any sequence of pushes and pops, with refused pushes leaving the state unchanged, the table equals $\Ins(a)$, where $a$ is the live sequence in push order.
\end{theorem}

\begin{IEEEproof}
Induction on the number of operations. A refused push changes nothing. A successful push of $x$ onto $\Ins(a)$ writes $x$ into the cell that the rule chooses from the occupied set, which gives $\Ins(a\cdot x)$ by definition. For a pop, $a=u\cdot x$ and the table is $\Ins(u)$ with $x$ additionally in the cell its insertion chose, because an insertion changes exactly one cell and that cell was empty in $\Ins(u)$; clearing it gives $\Ins(u)$ (Fig.~\ref{fig:undo}).
\end{IEEEproof}

The proof uses neither the lookup rule nor randomness, so it holds for adversarial names. What it proves is a statement about the \emph{index cells}: the set of occupied cells and their contents equal those of $\Ins(a)$. For \st\ the claim carries over to the bytes of the buffer only for the state that the operations define, and we state exactly which. We distinguish four levels, each tested over 66\,582 scope exits in eleven configurations (fixed, bounded and growable buffers, odd sizes, tiny buffers that refuse). (a)~\emph{Logical state} (every accessor, the lookup of every name, the invariants): equal to a fresh table of the live declarations in all exits. (b)~\emph{Allocated region} (index, identifier stack, undo stack): equal to a fresh table with the same index size in all exits; the identifier stack alone is equal even when the index size differs, because references are relative, whereas the index words and one-word undo entries differ across index sizes by construction. In growable mode the index is not shrunk at once, so after a scope exit it can be larger than that of a fresh table built from the live names, and equality with such a table holds only when the index is configured to the same size. (c)~\emph{Every supplied word}: never equal, because removal is by moving counters: dead records, popped undo entries and scope marks remain in the free gap between the two stacks, and the high-water statistics are history. Only the removed name's index slot is cleared. (d)~Against a fresh table with the same index and buffer size, the digest and the allocated region are equal in all exits and every differing word lies in the free gap. The proven claim is therefore (a) and (b) with equal configuration; a deployment that must not leave old identifiers readable in the free gap has to clear it itself. Two consequences matter below. The table does not age: no sequence of scope entries and exits lengthens probe paths. And in the random-function model, for a schedule that does not depend on the hash, the law of the index at every moment is that of an insertion-only table with the current number of live names, so classical insertion-only results~\cite{knuth3,janson2005} and the refusal law of Section~\ref{sec:bounded} apply to the next push at every moment up to the first refusal; Section~\ref{sec:bounded} states what holds afterwards.

\strfigwide[0.56\textwidth]{figures/fig_dep.pdf}{Dependency and orphans. Key $y$ probed cells 2, 3 and 4 before it was stored in cell 5, so it depends on $u$, $v$ and $w$. Clearing $w$ first leaves a hole on its path and orphans $y$; clearing the newest key never does.}{fig:dep}

Why is last-in-first-out order special? For a table built by $\Ins(x_1,\ldots,x_n)$ let $c(x)$ be the cell of $x$ and say that $y$ \emph{depends on} $x$, written $y \lhd x$, if $c(x)$ lies strictly before $c(y)$ on the probe path of $y$ (Fig.~\ref{fig:dep}). A deletion order is \emph{clear-safe} if, after every prefix of it has been cleared, every remaining key is still found.

\begin{theorem}[Safe orders]
\label{thm:exact}
Fix the homes of $x_1,\ldots,x_n$ ($2\le n\le m$) under linear probing. (a) A deletion order is clear-safe for these homes if and only if it is a linear extension of $\lhd$, that is, $y$ is deleted before $x$ whenever $y \lhd x$. (b) It is clear-safe for every assignment of homes if and only if it is the reverse insertion order.
\end{theorem}

\begin{IEEEproof}
(a) Clearing never moves a key. The lookup of a remaining key $y$ follows its probe path and stops at the first empty cell; the cells of that path before $c(y)$ were occupied, when $y$ was inserted, by the keys $x$ with $y\lhd x$. So $y$ is found if and only if none of them has been cleared. (b) A key that depends on $x$ is newer than $x$, so reverse insertion order is a linear extension of $\lhd$ for every assignment. Conversely, for $i<j$ give $x_1,\ldots,x_{j-1}$ distinct homes and give $x_j$ the home of $x_i$; then $x_j \lhd x_i$, so a universally safe order deletes $x_j$ before $x_i$ for every pair $i<j$.
\end{IEEEproof}

A scheme is \emph{greedy} if a key is stored in the first empty cell of its own probe sequence and a search for a key follows the same sequence and stops at the first empty cell; part (a) holds for every greedy scheme with these lookups, and the converse in part (b) is proved here for linear probing only. The number of keys that depend on a key quantifies the cost of leaving the discipline: it equals $Y_c-1$, where $Y_c$ follows the queue recursion $Y_c=(Y_{c-1}-1)^{+}+A_c$ with $A_c$ the number of keys homed at cell $c$, and for $n/m\to\alpha$ its law converges to that of a discrete M/D/1 queue, with mean and fraction of independent keys
\begin{equation}
\E[\mathrm{orph}]=\frac{\alpha}{2(1-\alpha)},\qquad \Prob(\mathrm{orph}=0)\to\frac{(1-\alpha)(e^{\alpha}-1)}{\alpha}.
\label{eq:orphan}
\end{equation}
At load $3/4$ only 37 percent of keys could be removed out of order without harm, and clearing a random key orphans 1.5 keys on average (Table~\ref{tab:orphan}). The limit law is Janson's Robin Hood displacement law~\cite{janson2005}; the reading as orphans of a deletion and the finite-size form are new as stated. This is why every deletion method for arbitrary order needs tombstones or shifting~\cite{knuth3,bender2021}, and why \st\ could not adopt a relocating deletion: its undo entries store index slots.

\section{Bounded Mode and the Exact Refusal Law}
\label{sec:bounded}

\subsection{Static Index and Probe Limit}
In the bounded mode the caller fixes the number of index slots $m$ when the table is created. The index is never rebuilt; a declaration that would exceed the load limit is refused like one that exceeds the buffer. The caller may also set a probe limit $L$. A new name is inserted only if an empty slot lies among the first $L$ slots of its probe path, and is refused with \code{probe-limit} otherwise (Algorithm~\ref{alg:declare}). Since a stored name never moves and scope exit only empties slots, every stored name lies within $L$ slots of its home, and a search may stop after $L$ slots. One call thus examines at most $L$ index words and, per fingerprint match, compares at most 64 name words (requirement R4). A name that hides a visible one needs no slot and is never refused for this reason.

\emph{From slot examinations to total work.} A call reads its name once, at most 255 bytes, to pack and hash it (at most 51 packed or 64 raw words), examines at most $L$ index words, and compares at most $\min(n_x,64)$ name words for each of those whose fingerprint and meta word match, where $n_x$ is the word count of the stored name. A declaration or lookup therefore performs at most $255 + L\,(1+64)$ elementary word operations whatever the names are; for $L=258$ this is 17\,025. The scratch space is one key of 268 bytes on the stack plus a handful of scalars, and no call is recursive. The bound excludes the scope exit, which is proportional to the number of declarations in the scope, the rebuild of the default mode, the generation of the key and the caller's own string handling, and, in growable mode, the allocator.

\subsection{How Often Does the Limit Refuse an Honest Name?}
\label{sec:law}
\emph{Probability model.} Throughout this subsection the hash is an ideal random function: the homes of distinct names are independent and uniform on the $m$ cells, and the schedule of operations does not depend on them. We consider an index of $m$ cells holding $n=m-k$ live names, $k\ge1$. By Theorem~\ref{thm:undo}, the table without a probe limit is the insertion-only table of its live names at every moment, so the probability that the next fresh name needs more than $L$ probes is that of an insertion-only linear-probing table with $n$ keys. For $g\ge1$ let $B(g)=g^{g-1}/g!$ and, for $j\ge0$, $Q_j(s)=\tfrac{j}{s}\,s^{s-j}/(s-j)!$ for $s\ge j\ge1$, with $Q_j(s)=0$ for $s<j$ and $Q_0(s)=[s=0]$. Four processes must be told apart, because the refusal rule makes the stored names depend on the hash.
\begin{itemize}
\item[(P1)] \emph{Ideal fill:} $n$ fresh names are inserted into a table without a probe limit.
\item[(P2)] \emph{First capped query:} the next fresh name is refused at limit $L$ iff its probe count in (P1) exceeds $L$. This is what Theorem~\ref{thm:law} computes, exactly.
\item[(P3)] \emph{Conditioned fill:} the same query, given that none of the $n$ earlier pushes would have been refused at limit $L$.
\item[(P4)] \emph{Operational process:} a table with limit $L$ that keeps receiving fresh names after refusing some of them; refused names are not stored.
\end{itemize}
The law is exact for (P2). It does not by itself describe (P3) or (P4), because the names that are accepted are selected by the refusal rule. Two facts give valid statements for them. For (P3), $\Prob(\text{refused}\wedge\text{clean fill})\le R_m(n,L)$, so the conditional probability is at most $R_m(n,L)/P_{\mathrm{fill}}$, where $P_{\mathrm{fill}}\ge1-\sum_{t<n}R_m(t,L)$ is the probability of a refusal-free fill (theory supplement~\cite{strata}). For (P4) with insertions only, couple the operational table $B$ with the ideal table $A$ that receives the same names: the occupied cells of $B$ are always contained in those of $A$, since a name that $B$ refuses leaves a cell empty that $A$ fills, and a name that $B$ accepts lands on or before the cell where $A$ places it, a cell that is already occupied in $A$ if it lies before. A refusal by $B$ needs $L$ occupied cells from the home, hence the same in $A$, so the probability that the $t$th offered fresh name is refused is at most $R_m(t-1,L)\le R_m(n_{\max},L)$ whatever the earlier refusals, and the expected number of refusals among $N$ offered fresh names is at most $N\,R_m(n_{\max},L)$. The coupling argument covers insertions only. With scope exits, a name accepted by $B$ and popped may free a cell that $A$ keeps occupied by a different name, the inclusion can fail, and for a schedule that oscillates after refusals we claim only the bound up to the first refusal and the experiments below. The claims also require that the offered names are fixed independently of the hash (Section~\ref{sec:keyed}).

\begin{theorem}[Exact refusal law]
\label{thm:law}
Let a ring of $m$ cells hold $n=m-k$ keys, $k\ge1$, with independent uniform homes under linear probing. The probability that a new key with an independent uniform home finds its first $L$ cells occupied is
\begin{equation}
R_m(n,L)=\frac{k}{m}\sum_{g=L+1}^{n+1}(g-L)\,\pi_g,\qquad \pi_g=\frac{B(g)\,Q_{k-1}(m-g)}{Q_k(m)}.
\label{eq:law}
\end{equation}
\end{theorem}

\begin{IEEEproof}[Proof sketch]
The sum ranges over block sizes $g\le n+1$. Cut the ring at its $k$ empty cells. Each empty cell and the run of occupied cells after it form a block; by the cycle lemma~\cite{dwass1969} block sizes are Borel distributed, and, conditioned on filling the ring, the $k$ blocks are exchangeable, so the first has size $g$ with probability $\pi_g$ by the Borel--Tanner identity~\cite{tanner1961}. A new key is refused exactly when its home starts a window of $L$ occupied cells; a block of $g$ cells contains $(g-L)^{+}$ such homes, and the expected number of blocks is $k$. The full proof is in the accompanying theory manuscript~\cite{strata}.
\end{IEEEproof}

$R_m(n,L)$ is nondecreasing in $n$ (the occupied set of unrestricted linear probing does not depend on the insertion order and adding a key only adds a cell, so a window of $L$ occupied cells persists), so the value at the load limit covers every lower load. Boundary cases are handled explicitly: for $k=1$ the law reduces to $(m-L)^{+}/m$. It is evaluated in logarithms with the log-gamma function, because $g^{g}$ and $s^{s}$ overflow double precision at $m=65\,536$, and it was compared with brute-force enumeration of every home sequence in exact rational arithmetic and with an independent derivation (Section~\ref{sec:verification}). As $n/m\to\alpha$ it converges to $(1-\alpha)\sum_{g>L}(g-L)\,\mathrm{Borel}(g;\alpha)$, and with $\rho=\alpha e^{1-\alpha}$
\begin{equation}
R_\infty(\alpha,L)\sim\frac{(1-\alpha)\,\rho^{L+1}}{\alpha\sqrt{2\pi}\,(1-\rho)^{2}\,L^{3/2}}\qquad(L\to\infty).
\label{eq:tail}
\end{equation}
The quantity is classical: it is the tail of the unsuccessful-search cost, whose generating function and Poisson limit are given by Janson and Viola~\cite{janson2016} and whose finite-size values follow from Knuth's run-length counting~\cite{knuth3}. What is new here is the short derivation of the explicit sum~\eqref{eq:law}, its validation against the implementation, and its use as a design rule. A Chernoff bound on the number of homes in an interval, which an earlier version of this study used, gives $\rho^{L}/(1-\rho)$; by \eqref{eq:tail} it is loose by a factor growing like $L^{3/2}$. At load $3/4$ and $65\,536$ slots the bound exceeds the exact value by a factor of 315 at $L=64$ and 4\,637 at $L=512$.

\emph{Per request and per compilation.} The value $\varepsilon$ is a probability per fresh-name request, not per compilation. A compilation that offers $N$ fresh names has, for an oblivious schedule, a probability of at least one refusal of at most $N\,\varepsilon$ by the union bound (exactly, for a monotone fill, the theory supplement gives $1-P_{\mathrm{fill}}$, which lowers the limit for a whole-fill target of $10^{-6}$ at $m=4096$ from 402 to 306 probes), and the expected number of refused names is at most $N\,\varepsilon$ by the coupling above. For instance, $N=10^{4}$ fresh names at $\varepsilon=10^{-6}$ give at most $10^{-2}$ for the compilation; a target of $10^{-6}$ for the whole compilation needs $\varepsilon=10^{-10}$. Repeated names do not consume slots, but a name that is popped and pushed again counts as a new request, and these requests are correlated; a retry of a refused name with an unchanged key and table is refused again, so retries add no independent chances. A schedule that adapts to observed refusals depends on the hash, and only the unconditional bound of $L$ probes holds for it. The theory supplement also gives the probability that a persistent set of names can never refuse a fresh one and a schedule-free bound for bounded churn above persistent names~\cite{strata}.

\subsection{Keyed Hash and the Lifetime of a Key}
\label{sec:keyed}
The default hash is the 32-bit MurmurHash3 mixer~\cite{murmur3} applied to the name words. As an option, the table hashes with HalfSipHash with one compression and three finalization rounds~\cite{aumasson2012,linuxsiphash} under a 64-bit key supplied by the caller, checked against the reference code~\cite{siphashref}. Theorem~\ref{thm:law} is a statement in the ideal model above. A keyed 32-bit hash with a 64-bit key is not a random function, and fresh keys do not make the homes of all names exactly independent; using the law for the practical table relies on the assumption that HalfSipHash-1-3 under an unknown key is indistinguishable from a random function by the adversary, which is its design goal and not a theorem, and the empirical agreement of Section~\ref{sec:probe} is evidence for names that are not adversarial. We make no cryptographic claim.

Under the assumption above, Theorem~\ref{thm:law} applies to chosen names only if the key is independent of everything the adversary has seen. If every table is created with a fresh key and the adversary is oblivious, that is, fixes its names before the key is drawn, the homes are modeled as independent and uniform and the law is used for every name set and scope schedule. A fresh key per translation unit limits what can be learned across tables; it does not by itself address an adaptive adversary who queries the same table, whose refusals or probe lengths reveal information about the key. If one key is reused across tables and the adversary can observe probe lengths, it can learn names that collide with a target cell and plant a long run of occupied cells: in an experiment against the real table with an idealized probe-length oracle ($m=2\,048$, $L=512$, 700 honest names, five seeds), 1 to 5.5 percent of honest names on average (6.1 percent at most over seeds) were refused with a persistent key and none with a fresh key or with the same number of random names (Table~\ref{tab:adaptive}). The rule is therefore one key per translation unit, derived from a device secret and a never-repeating counter, which must survive a restart of the device (a counter that restarts at zero repeats keys). The library only takes a caller-supplied 64-bit key; neither key derivation nor counter persistence is implemented, and our experiments use pseudo-random keys (flooding, refusal-law and adaptive runs) or one constant key (the keyed timing variant, the bounded traces and the embedded image), so the timing of the keyed variant says nothing about key derivation cost. The work bound of R4 does not depend on the key: a call examines at most $L$ slots whatever the names. The experiment above uses an idealized probe-length oracle; it measures what an adversary could learn if such a channel existed, not a timing channel.

\subsection{Colliding Identifiers for the Default Hash}
\label{sec:attack}
The mixer processes a name word $k$ as $h \leftarrow \mathrm{rotl}_{13}\bigl(h \oplus f(k)\bigr)\cdot 5 + c$, where $f$ multiplies, rotates and multiplies and is a bijection on 32-bit words that does not involve the seed. Following Aumasson and Bernstein~\cite{aumasson2012,aumassonslides}, flipping bit 18 of $f(k_1)$ flips bit 31 of the rotated word; multiplying by 5 and adding $c$ leaves that difference in bit 31 for every $h$; and flipping bit 31 of $f(k_2)$ in the next word cancels it. Two consecutive words can thus be exchanged without changing the hash, whatever the seed. Here a word must be a packing of five identifier characters, and a random search finds word pairs that satisfy the constraints for both alternatives within a fraction of a second. Concatenating $t$ such pairs gives $2^{t}$ distinct identifiers of $10t$ characters with one common hash; with $t=15$ this yields \FloodN\ valid C identifiers of 150 characters, which collide under the built-in seed and eight further seeds.

\section{Verification}
\label{sec:verification}
\emph{Unit and randomized differential tests.} A test program compares the table with an independent reference model (a separate implementation of the semantics in terms of standard containers that shares no code with the table) after every operation, in configurations that cover packed and raw names, fixed and growable buffers, a dense and a sparse index, failing allocators, and a hook that forces every key into one probe cluster. It requires a 64-bit digest of the complete state to be unchanged after every refusal and rebuilds a fresh table from the live declarations to compare memory. It makes \UnitChecks\ checks under AddressSanitizer and UndefinedBehaviorSanitizer with two compilers.

\emph{Tests added after the review of this article.} (i)~\emph{Direct comparison on refusal:} 783\,955 refusals were checked by comparing a saved byte-for-byte copy of the whole buffer, the options, the counters and the digest, not the digest alone; all were unchanged. The sweeps cover the capacity word by word, an exact threshold test (a call is accepted iff the free words reach the need: 529 probes at exactly the need accepted, 1\,592 at one word less refused), growable budgets and failure of the allocator at each of its first twelve calls. (ii)~\emph{Status precedence} was printed and checked: an invalid table gives \code{no-memory}; \code{empty-name} and \code{name-too-long} precede any memory check; \code{too-deep} precedes \code{no-memory} on entry; \code{no-memory} precedes \code{probe-limit}; \code{no-scope} on exit at depth zero. (iii)~\emph{Encodings:} round trips of packed and raw names of every length from 1 to 255, names that differ only in padding or in embedded zero bytes, high-bit bytes, all 256 type tags and depth 16\,383, with 1\,030 constructed names pairwise distinct in both modes. (iv)~\emph{State equality} at the four levels of Section~\ref{sec:undo}. These tests found no defect in the library.

\emph{Bounded exhaustive enumeration.} A second program starts every sequence from a freshly created table, enumerates every sequence of nine operations over $\{$enter, exit, declare $a$, $b$, $c$, $d\}$ ($6^9=10\,077\,696$ per configuration) in eight small configurations (fixed buffers of 128 to 256 bytes or a static index of 16 slots, packed and raw names, a forced single probe cluster, the keyed hash, probe limits 0, 1 and 2) chosen so that every kind of refusal occurs, over the alphabet of the two scope operations and four declarations of different names (including a non-identifier name stored raw). The buffer is refilled with a marker pattern and the reference model is recreated for every sequence. After each operation the result and the lookups of all four names are compared with the model and the invariants are checked, and after each refusal the digest is compared (not the bytes). It counts each executed operation: \ExhSeq\ sequences, \ExhOps\ operations, \ExhRefusals\ of them refused (a refusal being a returned error status other than exit at the outermost scope), no failure. It was run again on the final code, after the changes described in Section~\ref{sec:sessions}, with identical counts (2\,min\,39\,s). It is a finite check and not a proof of correctness.

\emph{Differential fuzzing and mutation.} A libFuzzer harness ran \FuzzBefore\ million executions on the code before the change of Section~\ref{sec:artifact} and \FuzzFinal\ million on the final code without a failure, and detected each of \Mutants\ injected single-line defects within a second; a further 60-second run on the final code (348\,786 executions) found nothing. After the last change to the library (the instruction-count changes of Section~\ref{sec:sessions}), every test listed here was run again: the unit, differential and added tests with \code{g++} 16.2.1 and \code{clang} 22.1.8, with and without the sanitizers; the enumeration of depth nine; 2.3 million further fuzzing executions without a failure; and the mutation check, which again detected all \Mutants\ defects, each within 2.4 seconds.

\emph{The analysis.} Theorem~\ref{thm:undo} was checked in 488\,919 state comparisons over five insertion rules, Theorem~\ref{thm:exact} on every assignment and every deletion order of small rings (397\,562 pairs), and the refusal law against brute-force enumeration of every home sequence in exact rational arithmetic (258 cases) and against an independent derivation by Knuth's Abel-binomial route (481 cases). The proofs are pen-and-paper; no proof assistant was used.

\section{Experimental Setup}
\label{sec:setup}

\subsection{Workloads}
\strfig{figures/fig_pipeline.pdf}{Evaluation method. Symbol-table events are logged by instrumented compilers and replayed on every table; an independent reference model decides correctness.}{fig:pipeline}

The workloads are sequences of symbol-table events produced by a real compiler (Fig.~\ref{fig:pipeline}). We added logging to the Tiny C Compiler~\cite{tcc} where it looks up an identifier, pushes a symbol, and opens or closes a scope, and compiled eight open-source C projects at pinned versions (Table~\ref{tab:workloads}). At the start of each translation unit every table is destroyed and created anew, as a compiler would do. \emph{Trace semantics.} A trace is a text file with one event per line: a unit start, scope entry and exit, a declaration and a lookup with an identifier. The API has one namespace, and the traces log only the ordinary-identifier namespace of C (variables, functions, typedef names, enumeration constants). Struct, union and enum tags, members, labels and macros are separate tables of the compilers and are not logged. In TinyCC the hooks sit in \code{sym\_find} (every lookup, including those that find nothing, which are 12.5 to 34 percent of the lookups), in \code{sym\_link} for non-tag symbols, and in the block, prototype and function-parameter scopes; file-scope pushes made while a local scope is open (implicit declarations) are logged separately and ignored by every replay. A declaration of a name already declared in the same scope is replayed as the API's same-scope replacement; the eight TinyCC traces contain none, while the chibicc traces contain 1 to 122 per project. Empty names that occur in chibicc (9\,324 lines) are dropped by the replay tools and stored as a single placeholder byte in the compiler integration. Sources are pinned by version tag or URL only; commit hashes and archive checksums were not recorded, and SHA-256 checksums of every trace file are published with the artifact. Three Mbed TLS units that TinyCC could not compile are skipped. The reference model that decides correctness is a separate implementation of the semantics above and shares no code with the table.

A second set of seven traces from an instrumented chibicc~\cite{chibicc} is used for the bounded-mode experiment, and nine synthetic traces stress cases that C programs rarely produce.

\subsection{Tables Compared}
\label{sec:baselines}
\NTables\ tables are driven through one interface.
\begin{itemize}
\item \st\ and four variants: raw instead of packed names, a sparse index (at most half full), no shrinking of the buffer, and the keyed hash.
\item \emph{The conventional arena table}, our main baseline: bucket heads, a stack of entries (chain link, hash, value, length and depth, unpacked name) and scope marks in one buffer, with the same storage discipline as \st. It was written as the strongest conventional design we could build, so that a comparison isolates the compact layout from the mere absence of an allocator.
\item One standard-library hash map per scope; an undo log over a standard-library map (the algorithm of LLVM's \code{ScopedHashTable}); the same over a Swiss-table map~\cite{phmap}; an interning Swiss-table map.
\item METIS-X~\cite{metis}, the predecessor, a Robin Hood table with one slot per declaration, and two further tables from its repository, used unmodified.
\end{itemize}

\subsection{Metrics and Procedure}
\emph{Correctness} is agreement with the reference model on every lookup and declaration result. \emph{Heap peak} counts every allocation with its usable size. The \emph{smallest fixed buffer} is found by bisection, at a resolution of 64 bytes, as the smallest buffer with which the whole trace replays without a refusal. \emph{Replay time} is the time to replay a whole trace on a fresh table. In each of \Rounds\ measured rounds, after two warm-up rounds, every table replays the trace once and the starting table rotates. For two tables we report the median over rounds of the ratio of their times (pairing is by round: both tables are replayed in the same round) with a 95 percent bootstrap interval from 2000 resamples of rounds of the percent change $100\,(r-1)$, and call a difference \emph{established} when the interval excludes zero (``n.e.'' otherwise); an established difference is not an equivalence claim, and a non-established one is not evidence of equal speed. Section~\ref{sec:sessions} repeats the comparison in independent sessions with an equivalence test.

\subsection{Environment}
All host measurements were taken on one machine: \EnvCPU, Windows Subsystem for Linux 2 with Ubuntu 22.04 (\EnvKernel), \EnvCompiler\ with \code{-O2}, the benchmark pinned to one core by \code{taskset} (the chibicc end-to-end driver is not pinned), run \code{\RunName} of the public artifact~\cite{strata}. The repeated sessions of Section~\ref{sec:sessions} ran on a different, shared native Linux machine described there. The embedded experiment uses \code{arm-none-eabi-g++} 10.3.1 with \code{-Os} and QEMU~\cite{bellard2005qemu} 6.2 emulating a Cortex-M3 board (\code{mps2-an385}) restricted to 64\,KiB of memory, without heap and without operating system. The refusal law was checked against the real bounded-mode table, with the keyed hash and a fresh random key per trial, in seven settings of 400\,000 trials.

\subsection{Anatomy of the Saving: An Exact Space Ledger}
\label{sec:ledger}
\strfigwide[0.85\textwidth]{figures/fig_ledger.pdf}{Saving of \st's layout over the conventional single-buffer layout on the eight traces, split into the stored hash word and name packing, from the exact space ledger.}{fig:ledger}

Every single-buffer layout considered here uses a number of words that is a sum of per-element costs, as in \eqref{eq:memory}. Let $C_0$ be the conventional layout, $C_1$ the same without the stored hash word, $C_2$ an open-addressed index over one entry per declaration (a layout rule evaluated by accounting only, no code), $S_{\mathrm{raw}}$ \st's layout with raw names and $S$ \st\ itself. Only $C_1$ was a layout rule at first; it is now implemented and measured (below). Subtracting the formulas gives exact identities at every instant:
\begin{equation}
U_{C_0}-U_{C_1}=d,\qquad U_{S_{\mathrm{raw}}}-U_{S}=\sum_{x\ \text{packable}}\Bigl(\Bigl\lceil\tfrac{\ell_x}{4}\Bigr\rceil-\Bigl\lceil\tfrac{\ell_x}{5}\Bigr\rceil\Bigr),
\label{eq:ledger}
\end{equation}
and interning with an undo log saves the names of hidden declarations but costs one extra word per open scope. The accounting reproduces all 24 measured minimum buffers to the 64-byte resolution of the measurement. On the eight traces, dropping the stored hash saves 9.2 to 12.2 percent and packing a further 5.3 to 9.0 percent, while interning changes the footprint by between $-0.38$ and $0.00$ percent (Fig.~\ref{fig:ledger}, Table~\ref{tab:ledger}).

\emph{The stronger baseline, measured.} We implemented $C_1$ as a real table: the conventional arena table with the same hash, load factor, growth and refusal behavior, entries of $3+w$ words, and the hash recomputed from the stored name wherever the stored word was used. Its measured smallest buffer equals the ledger's prediction exactly on all eight traces, and at that buffer all four tables agree with the reference model with no refusal, while 64 bytes less makes each refuse. Against $C_1$, \st\ needs \ConeSaveLo\ to \ConeSaveHi\ percent less (\ConeSavePooled\ percent pooled), against $C_0$ \CzeroSaveLo\ to \CzeroSaveHi\ percent (\CzeroSavePooled\ percent pooled; Table~\ref{tab:c1}); \st\ with raw names needs the same buffer as $C_1$ to within 64 bytes, so the remaining saving is name packing. The headline saving of one sixth is therefore a comparison with a conventional table that stores a hash word, and the saving against the stronger baseline is about one thirteenth. The smaller baseline costs time: $C_1$ replays \SessCCLo\ to \SessCCHi\ percent slower than $C_0$ (Section~\ref{sec:sessions}). Interning pays only in programs that shadow often, as the sweep of Section~\ref{sec:fit} confirms.

\label{sec:sessions}
Because the verdicts of single runs changed between runs, we repeated the replay-time comparison in five independent sessions: a new process per trace, \Rounds\ paired rounds after two warm-up rounds as before, the start order rotated by session, the process pinned to one core, sessions five minutes apart, with the stronger baseline $C_1$ added. The sessions ran on a different configuration from the first run: a native Linux desktop (kernel 7.2.4, \code{g++} 16.2.1, Intel Core i7-13620H, \code{intel\_pstate} governor \code{powersave}, turbo enabled), not WSL2 with \code{g++} 11.4. The machine is shared and not isolated: the frequency of the pinned core at the start of a session ranged from 0.6 to 4.7\,GHz, its sibling hardware thread was 1.4 to 5.8 percent busy, and the load average at the start was 0.4 to 2.5; absolute times differed by up to a factor of 1.5 between sessions, so only ratios are interpreted. The unit of replication is the session. For each pair of tables and trace we give the pooled median ratio of paired times with a 95 percent $t$ interval over the five session medians (4 degrees of freedom). ``Slower'' or ``faster'' means that the interval excludes 1. To test equivalence we use two one-sided tests with a stated practical margin, a ratio in $[0.90,1.10]$: ``eq'' if the 90 percent interval lies inside the margin, ``out'' if it lies outside, ``inc'' otherwise. The margin is a choice, not derived from the data. The comparisons are exploratory, not confirmatory; 32 intervals are reported without correction for multiplicity, and the eight traces are correlated through shared compiler behavior, so they are not eight independent samples of programs.

The sign of the difference to the arena table therefore did not reverse, but the earlier statement that no difference was established on most traces holds for the first run only; the first run and these sessions differ in compiler, kernel, processor and scheduling, and we cannot separate these factors. The practical conclusion is that the compact table is not faster than a conventional single-buffer table, and that in these sessions it is slower by \SessSZeroLo\ to \SessSZeroHi\ percent against the table with a stored hash and by up to \SessSOneHi\ percent against the one without.

\emph{Measurement details.} A replay time is one interval of the C++ steady clock (\code{clock\_gettime} with \code{CLOCK\_MONOTONIC}, 1\,ns resolution) around the replay of a whole trace, with no batching; table creation for each translation unit is inside the interval. The empty interval costs a median of 20\,ns (18\,ns for raw \code{clock\_gettime}, 13\,ns for \code{rdtscp}), negligible against replay times of hundreds of microseconds or more. Per-operation latencies (13 to 79\,ns) are taken with \code{rdtscp} with the median empty-pair overhead subtracted, which adds a fixed cost to every operation and may change the measured cost of the instrumented operation; the 95th percentile is taken over all samples of a whole trace pooled across translation units, as the median of three replays, so a translation unit with many operations weighs more. Raw paired rounds, the per-session context (load, frequency, busy fractions) and the exact commands are published with the artifact.

\emph{Instruction counts.} Wall-clock time on a shared machine depends on clock frequency and load. We therefore also counted the user-space instructions that a replay executes, with the processor's performance counters (\code{benchmarks/instr\_count.cpp}). Such a count does not depend on frequency or on other programs: the five replays of a table on a trace differed by at most 0.03 percent (Table~\ref{tab:instr}). \st\ executes 31 to 41 percent more instructions than $C_0$ and 21 to 29 percent more than $C_1$ on every trace, and the keyed variant 47 to 58 percent more than unkeyed \st. Counting the instructions of each step of a declaration locates most of the excess in the capacity check with its amortized index rebuilds, which must hash every name again because no hash is stored, and in writing the record, the index slot and the undo entry; with raw instead of packed names the count falls by only 8 to 9 percent. Each of these steps pays for a property of the design (the smaller buffer, exact undo, refusal without change), so we did not remove them. The count agrees in sign with the repeated sessions, which found \st\ slower, but not in size: the extra instructions cost 8 to 20 percent of time, because the replay is partly bound by memory accesses that are common to all tables. An instruction count belongs to one build: it does not depend on the clock or the load, but it does depend on the compiler and the instruction set, so these x86-64 counts say nothing direct about the Thumb-2 code of the microcontroller; it is not a time, and we do not convert it into one. Preparing the name is a large part of the work of both tables. When both tables are given names that were packed and hashed once before the replay (\code{benchmarks/prepared\_count.cpp}; construction and destruction of the table not counted), \st\ uses 38 to 45 percent fewer instructions and $C_0$ about one third fewer, and the excess of \st\ over $C_0$ falls from 43--54 to 18--44 percent (18 percent on SQLite, 35 to 44 percent on the others). This is a property of the interface (a compiler's lexer can prepare a name once), not a result about the tables as called here, and the time cost of the remainder was not measured. After the embedded and timing runs of this article were made, three small changes (one validity test per packed word with a compile-time character table, a fast path for the capacity check, and a plain loop in place of a library call for the short record copy) lowered the counts of \st\ by 6 to 8 percent; those runs used the earlier code, whose results are identical. Two further attempts gave no gain and were dropped: a cheaper hash step, and a one-entry cache of the last lookup, which hit on 17 to 28 percent of lookups but cost as much on the misses as it saved on the hits. Because the count is reproducible to within 0.03 percent, it is not subject to the instability that affected the timing verdicts.

\subsection{Hash Flooding and Its Defenses}
\label{sec:flood}
\strfig{figures/fig_flood.pdf}{Time to declare $N$ distinct names of 150 characters. Colliding names are those of Section~\ref{sec:attack}; ordinary names are random identifiers of the same length. Both axes are logarithmic.}{fig:flood}

In the default configuration the colliding names take \FloodCol\,ms to declare against \FloodOrd\,ms for ordinary names, a factor of \FloodRatio, and \FloodLookCol\,ms to look up; time grows with exponent \FloodExp\ in the number of names, since every new name scans the cluster formed by all earlier ones. With the keyed hash the factor is \FloodKeyedRatio: names built against the unkeyed mixer are ordinary names under a key their author does not know. With the unkeyed hash and a probe limit of 64, time grows linearly, at the price that \FloodBoundedRefused\ of the \FloodN\ colliding names are refused and only 64 are admitted: the capped table finishes quickly because it does almost no useful work, and its time is not comparable with that of a table that stores all names. Flood and honest names were never mixed in one table, so the number of honest names that a capped table would also refuse next to such a flood was not measured. The limit bounds the work of a call whatever the hash does. A keyed hash defeats the collision family built against the unkeyed mixer; that is evidence about this one family, not a proof that no collision strategy works, and a fresh key is argued under the assumptions of Section~\ref{sec:keyed}. \subsection{The Refusal Law Against the Implementation and the Traces}
\label{sec:probe}
\strfigwide[0.6\textwidth]{figures/fig_lawz.pdf}{Agreement of the exact refusal law with the real bounded-mode table: standard scores in seven settings of 400\,000 trials each, all within plus or minus 1.96.}{fig:lawz}

Each trial draws a fresh random 64-bit key, builds a table $A$ without a probe limit and a table $B$ with limit $L$ (same key, same index size), offers both the same $n$ random distinct names, and then offers one more fresh name. Table~\ref{tab:lawcheck} and Fig.~\ref{fig:lawz} compare the exact law with process (P2): the observed frequency, over \emph{all} trials, that the probe count of the last name in $A$ exceeds $L$, which is the event that $B$ would refuse it after a refusal-free fill. All seven $z$-scores lie within $\pm1.96$ (largest $|z|=1.96$). The \emph{clean} trials are those in which $B$ refused none of the $n$ earlier names; they are not used for the observed rate. In them $B$ was compared with $A$ in lock step (equal state digests and $B$ refuses the last name iff the probe count exceeds $L$), with no mismatch; this validates the equivalence of the limited and unlimited tables up to the first refusal, and says nothing about behavior after a refusal. That is the content of Table~\ref{tab:lawproc}: for each setting it lists the trials with a refusal in the fill, the refused fill operations, the frequency of a refusal of the last name given a clean fill (P3), and the frequency of a refusal of the last name in $B$ over all trials after it kept inserting past its refusals (P4). \subsection{An Emulated Microcontroller}
\label{sec:mcu}
We built a bare-metal image for a Cortex-M3 and ran it under QEMU with 64\,KiB of memory, with allocation functions stubbed to fail. Five of the eight traces fit that memory; all \EmbPass\ replay with a checksum over every result identical to the host's, using \EmbStack\ bytes of stack, and the table's code occupies \EmbCode\ bytes. The same \EmbBoundedPass\ traces pass in bounded mode with the keyed hash and a probe limit of 512, with no refusal. At equal buffers, \st\ fits FreeRTOS in 48\,KiB, Lua in 40\,KiB and cJSON in 32\,KiB, where the conventional table refuses 420, 2\,214 and 822 operations. The 64\,KiB limit is enforced by the linker script only, not by an emulator option; the trace input is constant data in flash and is not counted in it. The stack figure is the high-water mark of one run in fixed mode (492 bytes; 484 in bounded mode) measured by a painted stack region, and the code figure is the sum of the sizes of the \code{strata::} symbols in the unlinked object, not a linked image. The emulator provides no timing, and no physical device was used, so these results show that the code fits, runs and returns identical answers within the stated memory, not how fast it runs on a chip. The results that the embedded experiment supports, that the table fits, runs without a heap and gives the host's answers within the stated memory, and the mathematical results of Sections~\ref{sec:undo} and~\ref{sec:bounded}, do not depend on a physical device; a claim about speed on a device would, and none is made. The instruction counts of Section~\ref{sec:sessions} are of the x86-64 host build and are not a substitute for such a timing.

\section{Discussion}
\label{sec:discussion}

\emph{What the compact design buys.} Against a conventional chained table that obeys the same storage discipline and stores a hash word, \st\ offers a buffer about one sixth smaller; against the same table without the hash word, which we implemented and measured, the buffer is \ConeSaveLo\ to \ConeSaveHi\ percent smaller, all of it from name packing. In the first run no difference in speed was established on most traces; in five repeated sessions on another configuration \st\ was slower than both conventional tables (\SessSZeroLo\ to \SessSZeroHi\ percent against the one with the hash word). A conventional table can obtain most of the saving by dropping its stored hash, at a cost in time of its own. For a compiler on a workstation neither table matters. For a front end with tens of kilobytes, one sixth of the symbol table is memory that can go elsewhere, and on the emulated microcontroller it decided whether three workloads fit.

\emph{What the storage discipline buys.} One buffer and write-after-reserve give a refusal that is simple to state and simple to test exhaustively at small scale. We consider this the more transferable result; it applies equally to the conventional table.

\emph{Why last-in-first-out removal matters beyond speed.} The removal rule was adopted to avoid tombstones. Its more useful consequence is Theorem~\ref{thm:undo}: because the index is always that of an insertion-only table, the classical exact analysis of linear probing applies to it, in the ideal-hash model and up to the first refusal, at every moment, and Theorem~\ref{thm:exact} shows that for linear probing no other deletion order allows this for every table.

\emph{Why measurement alone was not enough.} Three times in this work a first measurement supported a conclusion that a closer measurement or the analysis overturned: the size of the time penalty of Section~\ref{sec:artifact} (found by per-operation profiling), the probe limit of 64 that the traces suggested (overturned by the refusal law), and the reading of the buffer saving as a benefit of interning (overturned by the ledger). These are arguments for pairing replay experiments with a baseline that shares the design's constraints and with an exact analysis of the quantity being tuned.

\emph{Where the design is the wrong choice.} If memory is not constrained and the input is trusted, this study gives no reason to prefer a single-buffer table. If the input is untrusted, the keyed hash costs \KeyedLo\ to \KeyedHi\ percent of replay time, and its guarantee requires a fresh key per table.

\section{Limitations and Threats to Validity}
\label{sec:limits}

\emph{Mostly replay, not compilation.} The traces record what a compiler's own tables were asked to do; replaying them measures a table, not a compiler built on it. The one experiment inside a compiler replaces variable scopes only, on a hosted machine, and shows no end-to-end benefit.

\emph{Two machine configurations, no hardware.} Timing comes from two configurations, a laptop under a hypervisor and a shared native desktop, and the microcontroller is emulated. The verdicts on individual traces are not stable across runs: in an earlier run of the same code \st\ was faster than the conventional table on two traces and slower on three, and in the repeated sessions it was slower on all eight. The sessions are not on an isolated machine (frequency scaling, a lightly loaded sibling thread). The traces are correlated, the intervals are exploratory and uncorrected for multiplicity, and the equivalence margin of $\pm10$ percent is a choice. The only claim the timing supports is that the compact table is not faster than a conventional single-buffer table.

\emph{Workloads.} The traces are C only, from two small compilers, and depend on the host's system headers. Names outside the identifier alphabet, as in mangled C++ names, take the unpacked path, which the traces exercise little.

\emph{Baselines.} The single-buffer baselines that decide the headline saving and the timing comparison, $C_0$ and $C_1$, were written by the authors of the table under study and are not independent implementations; we matched their hash, load factor, growth and refusal behavior to \st's so that a comparison isolates one design choice. The heap baselines wrap independently maintained containers (the C++ standard library and the parallel-hashmap Swiss table~\cite{phmap}), but they do not obey the single-buffer discipline, so they bear on the allocation question only. LLVM's own \code{ScopedHashTable} was not measured.

\emph{The analysis.} The proofs are pen-and-paper, checked by exhaustive enumeration and by comparison with the implementation, not by a proof assistant. The refusal law assumes an ideal hash; against an adversary it assumes that HalfSipHash with one and three rounds and a 64-bit key behaves as one and that keys are fresh. The key-lifetime experiment uses an idealized oracle; no timing channel was measured. A limit law for refusals on wide and deep scope trees is open.

\emph{Design limits.} Names of at most 255 bytes, 16\,383 nested scopes, a buffer of at most 64\,MiB, one name space per table, single-threaded use.

\emph{Literature.} The search for related work was limited, and several sources were consulted at the level of abstracts or documentation.

\section{Conclusion}
\label{sec:conclusion}
A scoped symbol table can be confined to one fixed buffer, refuse cleanly when the buffer is full, and, in bounded mode, bound the index slots examined by each declaration and lookup on hostile input (scope exit and the default-mode rebuild are not bounded this way), at a cost that we have measured and with a refusal probability that we can compute in the ideal-hash model. On events logged by a C compiler for eight projects, the compact design studied here needs a buffer about one sixth smaller than a conventional single-buffer table, a saving that an exact ledger attributes to a stored hash word and name packing, a saving that falls to between 5 and 9 percent against a conventional table without a stored hash word, which we implemented and measured. In time it is not faster: slower than both conventional tables in repeated sessions on one configuration, with no difference established on most traces in an earlier run. Both are well ahead of a multi-allocation predecessor, and that larger gain belongs to the storage discipline. Because declarations are removed in the reverse order of their creation, the index is always that of an insertion-only table; for linear probing this is the only deletion order with this property for every table, and it makes the refusal probability of a probe limit exactly computable in the ideal-hash model: at load three quarters and 65\,536 index slots, a refusal probability of one in a million per request needs 258 probes, not the 455 a tail bound suggests, and the law agrees with the implementation for the first capped query, with proved bounds for the process after refusals. Identifiers that collide for every seed of the default hash slow declarations 300-fold, and a keyed hash removes the effect for that collision family; under the stated assumptions a fresh key per table keeps the refusal law valid against an oblivious adversary.

The most useful next steps are a compiler that runs on the table on a physical microcontroller, workloads from languages other than C, a limit law for refusals on deep scope trees, and machine-checked proofs.

\section{Proof of the Exact Refusal Law and of the Bounds for the Refusal-Filtered Process}
\label{app:proof}
Let $k=m-n\ge1$. For $k=1$ one cell is empty and uniformly located, and the $L$ cells from a uniform start are occupied iff the start lies among the $(m-L)^{+}$ cells that precede the empty cell by at least $L$. Assume $k\ge2$ and let $X_j$ be the number of keys with home $j$; $(X_j)$ is multinomial with probability proportional to $\prod_j 1/x_j!$.

\emph{Step 1: blocks.} Since $n<m$ there are exactly $k$ empty cells, and the occupied set does not depend on the insertion order~\cite{konheim1966}. Cut the ring at the empty cells: a \emph{block} is an empty cell together with the occupied cells after it up to the next empty cell, so a block of $g$ cells has $g-1$ occupied ones. No key crosses an empty cell, so the keys homed in a block occupy exactly its cells. With home counts $y_u$ of the $g-1$ occupied cells, the cells are occupied and the next one is empty iff $\sum_{t\le u}y_t\ge u$ for $u<g-1$ and $\sum_{t\le g-1}y_t=g-1$. Conversely, a cyclic concatenation of such blocks has exactly these empty cells, so home-count vectors correspond bijectively to placements of $k$ blocks around the ring.

\emph{Step 2: weight of a block.} Put $y_g=0$ and $z_t=y_t-1\ge-1$. The condition says that the walk $z_1+\dots+z_u$ stays nonnegative for $u<g$ and first reaches $-1$ at $u=g$. By the cycle lemma~\cite{dwass1969}, exactly one of the $g$ cyclic rotations of a sequence in $\mathbb N^{g}$ with sum $g-1$ has this property. The weight $\prod_t 1/y_t!$ is rotation invariant and $\sum_{\sum y=g-1}\prod_t 1/y_t!=g^{g-1}/(g-1)!$ by the multinomial theorem, so the total weight of a block of $g$ cells is $B(g)=g^{g-1}/g!$.

\emph{Step 3: the block of a cell.} The weight of a ring configuration is the product of its block weights. Cell $0$ lies in a block of $g$ cells at one of $g$ positions; the remaining $k-1$ blocks contain $m-g$ cells with total weight $Q_{k-1}(m-g)$, where $Q_j(s)=\sum_{g_1+\dots+g_j=s}\prod B(g_i)=\tfrac{j}{s}\,s^{s-j}/(s-j)!$ by the Borel--Tanner identity~\cite{tanner1961}. By exchangeability, $\sum_g g\,B(g)Q_{k-1}(m-g)=\tfrac mk Q_k(m)$, hence cell $0$ lies in a block of $g$ cells with probability $\tfrac km\,g\,\pi_g$, $\pi_g=B(g)Q_{k-1}(m-g)/Q_k(m)$, at a uniform position.

\emph{Step 4: distance to the next empty cell.} For position $o\in\{2,\dots,g\}$ of a block of $g$ cells the next empty cell is $g+1-o$ steps away, so the $L$ cells from a start are all occupied iff $o\le g+1-L$, which holds for $(g-L)^{+}$ positions; position $1$ is empty. Therefore the probability that the first $L$ cells from an independent uniform home are occupied is $\sum_g \tfrac km g\,\pi_g\,(g-L)^{+}/g=\tfrac km\sum_{g>L}(g-L)\pi_g$, with $g\le n+1$.

\emph{Bounds for (P3) and (P4).} (P3): $\Prob(\text{refused}\mid\text{clean})=\Prob(\text{refused}\wedge\text{clean})/\Prob(\text{clean})\le R_m(n,L)/P_{\mathrm{fill}}$, and $P_{\mathrm{fill}}\ge1-\sum_{t<n}R_m(t,L)$, because the event that some push of the fill is refused at limit $L$ is the event that some push of the unlimited fill has probe count above $L$, a union of events of probability $R_m(t,L)$. (P4), insertions only: let $A$ be the unlimited table and $B$ the limited one, both receiving the same fresh names; we show $\mathrm{occ}(B)\subseteq\mathrm{occ}(A)$ by induction. If $B$ refuses a name, $B$ is unchanged and $A$ only adds a cell. If $B$ accepts a name at cell $c_B$, the cells of its probe path before $c_B$ are occupied in $B$ and therefore in $A$, so $A$ places the name at a cell $c_A$ at or after $c_B$ on the path, and $c_B\in\mathrm{occ}(A)\cup\{c_A\}$. If $B$ refuses a name, its first $L$ cells are occupied in $B$ and therefore in $A$; so $B$ refuses only if the probe count in $A$ exceeds $L$. The home of the offered name is independent of the table, hence the probability of refusal at the $t$th offer is at most $R_m(t-1,L)$.
