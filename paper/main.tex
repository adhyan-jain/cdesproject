\title{Bounded-Memory Scoped Symbol Tables on Compiler-Generated Traces: What Allocation-Free Storage Buys and What Interning Adds}

\begin{abstract}
A compiler that must run in little memory needs a symbol table whose size is bounded in advance and whose behaviour at the bound is defined. We study how much of that goal is reached by storage discipline alone and how much by the table's design. Three tables are compared in depth: METIS-X, our earlier Robin Hood table with one slot per declaration; a conventional chained table over an entry arena, written here as an allocation-free baseline; and \st{}, which interns each visible name once, keeps the innermost declaration in the name's record and saves hidden declarations on an undo stack. Both new tables live in one caller-suppliable buffer and refuse an operation without changing state when it is full. All tables replay the symbol-table calls that an instrumented Tiny C Compiler makes on \NTraces{} open-source projects, with \Rounds{} interleaved rounds and paired statistics. The conventional table already needs \ArenaVsMetisMemMin--\ArenaVsMetisMemMax\% less memory than METIS-X and is \ArenaVsMetisTimeMin--\ArenaVsMetisTimeMax\% faster. \st{} needs a further \FixArenaMin--\FixArenaMax\% less memory than the conventional table, \BpdMin--\BpdMax{} bytes per live declaration, but is slower than it on \ArenaSlowerN{} of \NTraces{} traces (median \ArenaSlowMed\%); it is faster on synthetic workloads with heavy shadowing. Most of the improvement over METIS-X therefore comes from removing per-name allocation, not from \st{}'s specific structure. We give a correctness argument for the all-or-nothing behaviour with tests that include adversarial collisions, and we run \st{} on an emulated bare-metal Cortex-M3 with 64\,KiB of RAM. Nothing was integrated into a compiler or run on hardware, and we claim no new algorithm.
\end{abstract}

\section{Introduction}
A scoped symbol table maps identifiers to declarations and forgets a block's declarations when the block ends~\cite{aho2006}. For a compiler that runs on a small device, or inside a tool with a fixed memory budget, three properties matter that general-purpose containers do not give: a memory bound fixed before compilation starts, no allocator calls during compilation, and a defined result when the bound is reached.

This paper continues the METIS-X project~\cite{metis}, a flat Robin Hood table~\cite{celis1985} with one 32-byte slot per declaration and short names stored in the slot. Its authors closed it with three findings: every component was known, the traces were extracted from source text by regular expressions, and a string-keyed table has no place in a compiler that interns identifiers first, as the Tiny C Compiler (TCC)~\cite{tcc} does.

A first version of this work reported that a redesigned table, \st{}, used far less memory than METIS-X. A review of that version asked whether the gain came from the design or simply from no longer allocating per name. This paper answers that question, and its claims are limited accordingly:
\begin{enumerate}
\item An audit of METIS-X with one reproduced correctness defect (Section~\ref{sec:audit}).
\item Two bounded-memory tables with the same storage discipline: a conventional arena table and \st{} (Section~\ref{sec:design}), with a correctness argument and tests for refusal without state change (Section~\ref{sec:correct}).
\item Traces of the real symbol-table calls of TCC on \NTraces{} projects (Section~\ref{sec:method}).
\item A decomposition of the improvement over METIS-X into the part due to allocation-free storage and the part due to \st{}'s structure, with paired statistics (Section~\ref{sec:results}).
\end{enumerate}
We do not claim a new algorithm; Section~\ref{sec:related} names the source of each mechanism.

\section{Audit of the Previous Implementation}
\label{sec:audit}
We read METIS-X at commit \code{7b3dacf}. \emph{Hard failure under deep shadowing:} all declarations of one name share a hash value and one probe cluster; the probe distance is an 8-bit field capped at 250, and an insertion beyond it is refused. On a trace that declares one name in 400 nested scopes METIS-X refused \DeepRefused{} declarations and returned \DeepWrong{} wrong lookup results; no other table failed. \emph{Lookup cost grows with shadowing:} every live declaration of the name is compared. \emph{Allocation per long name:} names over 12 bytes are heap blocks. By inspection only: rehash is not exception-safe, the slot array never shrinks, each scope owns a heap vector. In the earlier evaluation the heap figures included harness data, the main baseline never reclaimed names, and latency was timed per call with a clock as expensive as the call.

\section{Two Bounded-Memory Tables}
\label{sec:design}
Both tables keep all state in one array of 32-bit words that the caller may supply (fixed mode) or that grows by half through \code{realloc} (growable mode). Neither throws; in fixed mode neither allocates.

\subsection{Conventional arena table}
This is the classic compiler design, as in lcc-style compilers and TCC's symbol stacks: bucket heads at the bottom of the buffer, a stack of entries above them, scope marks at the top. An entry (16 bytes plus the unpacked name) is created for every declaration and linked at the head of its hash chain, so the first match in a chain is the innermost declaration. Scope exit unlinks and pops the scope's entries.

\subsection{\st{}}
The index is an open-addressing array with linear probing; a slot holds an 8-bit fingerprint and a 24-bit reference. The identifier stack holds one record per distinct visible name: value, a meta word (name length in words, type tag, scope depth of the innermost declaration) and the name, packed five characters to a word in the manner of RADIX-50~\cite{radix50}. The undo stack grows down from the end of the buffer (Fig.~\ref{fig:layout}).

A lookup packs and hashes the query, probes, and reads the innermost declaration from the record; its cost does not depend on shadowing depth. A declaration of a new name appends a record, fills a slot and pushes that slot's index (one word) on the undo stack. A declaration that shadows pushes the record's current value and tag (three words) and overwrites them. A redeclaration at the current depth replaces the value. Scope exit pops entries down to the scope's mark: a shadow entry restores what it saved; a first-declaration entry empties the recorded slot. Because the index grows by re-inserting records oldest first, the entries of first declarations are rewritten after each rebuild.

Limits: names of 1--255 bytes, depth 16{,}383, buffer 64\,MiB. A rebuild is linear in the number of live names. The hash, MurmurHash3's 32-bit mixer~\cite{murmur3}, is unkeyed.

\section{Correctness of the Guarantees}
\label{sec:correct}
\emph{Scope exit needs no tombstones.} In linear probing without displacement a key is stored in the first empty slot of its probe path and never moves, so the path of a key consists of slots filled by older keys. The name being removed at scope exit is the newest key in the index; it lies on no remaining key's path, and emptying its slot cuts no path. The same holds for each next entry. Rebuilding oldest first preserves the premise.

\emph{All-or-nothing.} Each operation validates, reserves, then writes. The reservation step either guarantees room for every word and index slot the operation will write, or fails before anything is modified; in growable mode the only fallible step, the allocator call, comes first. After it, no step can fail.

\emph{Tests.} A digest of the complete state (counters, index, both stacks) is taken before every operation and must be unchanged after every refusal, in 30 configurations: five buffer sizes, three workloads (random, deep shadowing, deep nesting), with the normal hash and with every key forced into one probe cluster. Each run is also compared with a reference model and unwound to empty. Further tests use an allocator that fails after $k$ calls, 5{,}000-deep shadowing of one name, and scope exit across index rebuilds. All pass under AddressSanitizer and UndefinedBehaviorSanitizer. The argument is informal; nothing was machine-checked.

\section{Methodology}
\label{sec:method}
\emph{Traces.} We added logging to TCC (commit \code{43c7708}) at \code{sym\_find} (lookup), \code{sym\_link} and \code{global\_identifier\_push} (declaration of ordinary identifiers), and at every change of its scope level. The patched compiler compiled cJSON 1.7.18, littlefs 2.9.3, zlib 1.3.1, Lua 5.4.7, FreeRTOS-Kernel 11.1.0, Mbed TLS 3.6.2 (three files that TCC rejects are missing), TinyCC itself and the SQLite 3.46.0 amalgamation (Table~\ref{tab:work}). Each translation unit starts with a fresh table. Struct tags, members, labels and macros live in other TCC tables and are not traced.

\emph{Tables.} \st{} in four configurations; the conventional arena table; METIS-X and its two baselines, unmodified; a hash map per open scope; the undo-log algorithm of LLVM's \code{ScopedHashTable}~\cite{llvmsht} on \code{std::unordered\_map} and on a Swiss-table node map~\cite{phmap}; and an interning Swiss flat map with dense per-identifier heads, mirroring the split between interning and resolution in Clang~\cite{clangident}. All implement the same operations with the same semantics.

\emph{Measurements.} (i) Every result is compared with a reference model built on \code{std::map}. (ii) Heap is measured through an allocator hook using \code{malloc\_usable\_size}; for the two bounded tables we also find by bisection the smallest fixed buffer that replays a trace without a refusal, because growth in steps quantises peak heap. (iii) Time: \Rounds{} rounds after two warm-up rounds; in each round every table replays the whole trace once, in an order rotated from round to round. For two tables we take the per-round relative difference and report its median with a 95\% bootstrap interval; a difference is \emph{established} when the interval excludes zero. (iv) Per-call latency uses the time-stamp counter with the cost of an empty interval (\TimerNs\,ns) subtracted; it is near the method's resolution and secondary. Runs were pinned to one core of an Intel Core Ultra 7 258V under Linux (WSL~2), GCC 11.4, \code{-O2}.

\subsection{Where the gain comes from}
Table~\ref{tab:dec} places the conventional arena table between the two. Its smallest fixed buffer is already \ArenaVsMetisMemMin--\ArenaVsMetisMemMax\% below METIS-X's peak heap, and it replays the traces \ArenaVsMetisTimeMin--\ArenaVsMetisTimeMax\% faster than METIS-X. \st{}'s buffer is a further \FixArenaMin--\FixArenaMax\% smaller, \BufMin--\BufMax\,KiB or \BpdMin--\BpdMax{} bytes per live declaration. But \st{} is established slower than the conventional table on \ArenaSlowerN{} of \NTraces{} traces, by \ArenaSlowMin--\ArenaSlowMax\% (median \ArenaSlowMed\%).

At the memory peak the number of live declarations equals the number of distinct live names on all traces but one: C code as TCC compiles it has almost no shadowing there. Interning therefore saves nothing on these traces; \st{}'s memory advantage comes from its smaller record and packed names, and its time disadvantage from packing the query and probing an open-addressing index instead of following a short chain that stores full hashes. We did not separate these two causes. On synthetic traces \st{} is established faster than the conventional table on \SynArenaFaster{} of \SynN{} (those with heavy shadowing, scope churn, a large repeated scope, or very short names) and slower on \SynArenaSlower.

\section{Related Work}
\label{sec:related}
A single hash table with an auxiliary stack unwound at scope exit is described in compiler textbooks~\cite{appel1998,aho2006} and implemented in LLVM's \code{ScopedHashTable}~\cite{llvmsht}; chained tables over arenas popped at scope exit are equally standard, and TCC keeps a per-token symbol pointer with symbol stacks~\cite{tcc}. Clang separates an identifier table from a resolver~\cite{clangident}. Fingerprints beside the key follow Swiss tables~\cite{swisstables}. Deletion in linear probing normally needs tombstones or shifting~\cite{knuth3,bender2021}; last-in first-out deletion needs neither. Character packing goes back to RADIX-50~\cite{radix50}, stack-like allocation by lifetime to arena allocators~\cite{hanson1990}. Our search of prior work was not systematic.

\section{Limitations}
Neither bounded table was integrated into a compiler; replaying TCC's calls measures tables, not compilation. The target run is an emulator, not a device. Traces reflect one compiler and C only. Timings come from one laptop under a hypervisor. All baselines except METIS-X's were written by us after known designs; they are not the production code of LLVM or Clang. The exception-safety defect of METIS-X was found by inspection. The correctness argument is informal.

\section{Conclusion}
On compiler-generated traces, most of what a bounded-memory symbol table gains over METIS-X comes from keeping names and entries in one allocation-free arena, which a conventional chained table already does and does faster. Interning with an undo stack and packed names saves a further sixth of the memory, gives lookups that do not depend on shadowing depth and wins when shadowing is heavy, at the price of slower operation on ordinary C code. Which of the two is preferable depends on whether memory or time is the binding constraint. The next steps are to replace TCC's own tables with each design and measure compilation, and to run on a device.
