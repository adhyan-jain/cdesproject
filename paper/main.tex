\begin{abstract}
A compiler that must itself run in little memory needs a symbol table whose size can be bounded in advance. Our earlier table, METIS-X, stored one 32-byte slot per declaration and one heap block per name longer than 12 bytes, and an audit found that it refuses declarations when one name is shadowed about 250 levels deep. We rebuilt the table around a different key. \st{} interns each visible name once, keeps the innermost declaration in the name's record, saves hidden declarations on an undo stack, and places everything in one contiguous buffer that the caller may supply. Scopes are last-in first-out, so leaving a scope pops two stacks and empties the newest index slots; no tombstones or shifts are needed. The algorithm is the textbook undo-stack symbol table; what is specific here is the single budgeted buffer with a defined failure result. We evaluate ten tables on the symbol-table calls that an instrumented Tiny C Compiler makes while compiling \NTraces{} open-source projects. \st{} agrees with a reference model on all traces, has the lowest peak heap on all of them (\HeapRedMin--\HeapRedMax\% below METIS-X), makes \AllocRedMin--\AllocRedMax\% fewer allocator calls, and replays the traces \TimeRedMin--\TimeRedMax\% faster than METIS-X, although on \NOverlap{} traces the confidence intervals overlap. In fixed-buffer mode it needs \BpdMin--\BpdMax{} bytes per live declaration. It does not improve lookup latency, its scope exit is slower than METIS-X's, and an interning flat hash map is faster on most traces while using more memory. The table was not integrated into a compiler and was not run on a microcontroller.
\end{abstract}

\section{Introduction}
A scoped symbol table maps identifiers to declarations and forgets the declarations of a block when the block ends~\cite{aho2006}. On a hosted compiler its memory is negligible. On a compiler that runs on the target itself, or inside a tool with a fixed memory budget, three properties matter that general-purpose containers do not offer: a bound on memory that can be fixed before compilation starts, no allocator calls during compilation, and a defined result when the bound is reached.

This paper continues the METIS-X project~\cite{metis}. METIS-X was a flat Robin Hood table~\cite{celis1985} with one slot per declaration and short names stored in the slot. Its authors closed the project with three findings of their own: every component was known, the traces had been extracted from source text with regular expressions, and a string-keyed table has no place in a compiler that interns identifiers first, as the Tiny C Compiler (TCC)~\cite{tcc} does.

We take those findings as the starting point and contribute the following.
\begin{enumerate}
\item A source-level audit of METIS-X (Section~\ref{sec:audit}) with one reproduced correctness defect.
\item \st{} (Section~\ref{sec:design}), a table that is itself the interner and the scope mechanism, in one buffer with a hard budget.
\item Traces of the real symbol-table calls of TCC on \NTraces{} projects, replacing the heuristic traces (Section~\ref{sec:method}).
\item A comparison of ten tables with all results reported, including those where \st{} loses (Section~\ref{sec:results}).
\end{enumerate}
We do not claim a new algorithm. Section~\ref{sec:related} names the source of each mechanism.

\section{Audit of the Previous Implementation}
\label{sec:audit}
We read METIS-X at commit \code{7b3dacf}. The findings that shaped the redesign are these.

\emph{Hard failure under deep shadowing.} All declarations of one name share a hash value and therefore one probe cluster. The probe distance is an 8-bit field capped at 250, and an insertion that would exceed it is refused. On a trace that declares one name in 400 nested scopes, METIS-X refused \DeepRefused{} declarations and returned \DeepWrong{} wrong lookup results; no other table failed.

\emph{Lookup cost grows with shadowing.} The lookup compares every live declaration of the name and keeps the deepest.

\emph{Allocation per long name.} Names over 12 bytes are heap blocks. The repository's claim that 93.4\% of names fit in 12 bytes is not supported by its own traces.

\emph{Rehash is not exception-safe}, the slot array never shrinks, and each scope owns a heap vector. These three were established by reading the code.

\emph{Measurement.} The published heap figures included a set of all names built by the harness inside the measurement window; the main baseline never reclaimed names; latency was measured per call with a clock about as expensive as the call.

\section{Design}
\label{sec:design}
\subsection{Layout}
\st{} keeps all state in one array of 32-bit words (Fig.~\ref{fig:layout}). The \emph{index} is an open-addressing array with linear probing; a slot holds an 8-bit fingerprint and a 24-bit reference to an identifier record. The \emph{identifier stack} grows upward and holds one record per distinct visible name: a value word, a meta word (name length in words, an 8-bit type tag, the scope depth of the innermost declaration) and the name. The \emph{undo stack} grows downward from the end of the buffer.

\subsection{Operations}
\emph{Lookup.} The query is packed, hashed and probed; a slot is examined further only if its fingerprint matches. The record found holds the innermost declaration, so the cost does not depend on shadowing depth.

\emph{Declaration.} If the name is not present, a record is appended, an index slot is filled and one word (the record's reference) is pushed on the undo stack. If the name is present with the current depth, the declaration is replaced and the call reports a redeclaration. Otherwise the record's current value and tag are pushed on the undo stack (three words) and overwritten. All space is reserved before anything is written, so a refused declaration changes nothing.

\emph{Scope entry} pushes a two-word mark holding the identifier-stack top.

\emph{Scope exit} pops undo entries down to the mark, restoring hidden declarations, then removes the names first seen in the scope. Those names are the most recently inserted keys of the index. In linear probing a key is placed in the first free slot of its probe path, so no older key's path depends on a newer key, and the newest keys can be removed by emptying their slots. No tombstones accumulate and nothing is shifted. Two passes are used: the slots are located first and emptied afterwards, because emptying one could cut the path to another.

\subsection{Names}
Characters of C identifiers are packed five to a word, six bits each; names containing other bytes are stored unpacked with a flag. The query is packed once and compared word by word, so stored names are never unpacked. The idea follows DEC's RADIX-50 encoding~\cite{radix50}.

\subsection{Memory modes}
In \emph{fixed} mode the caller supplies the buffer and the table never allocates. When the buffer is full, declarations and scope entries return an out-of-memory status. The index starts at 16 slots and doubles in place: the identifier stack is moved up and the index is rebuilt by re-inserting the records oldest first, which preserves the removal property above. In \emph{growable} mode the buffer grows by half through \code{realloc}, up to an optional budget, and is halved when less than a quarter is in use. A failed allocation leaves the table unchanged. No operation throws.

\subsection{Limits}
Names of 1--255 bytes, scope depth 16{,}383, buffer 64\,MiB. A rebuild is linear in the number of live names, so worst-case latency of a declaration is not constant. The hash (MurmurHash3's 32-bit mixer~\cite{murmur3} over packed words) is unkeyed.

\section{Methodology}
\label{sec:method}
\subsection{Compiler traces}
We added logging to TCC at commit \code{43c7708} where it touches its symbol tables: \code{sym\_find} (lookup), \code{sym\_link} and \code{global\_identifier\_push} (declaration of ordinary identifiers), and every change of its scope level, including prototype parameter scopes. \subsection{Tables compared}
Three configurations of \st{}; METIS-X and its two baselines, unmodified; and four tables written for this study on standard containers: a hash map per open scope; the undo-log algorithm of LLVM's \code{ScopedHashTable}~\cite{llvmsht} on \code{std::unordered\_map} and on a Swiss-table node map~\cite{phmap}; and an interning Swiss flat map with dense per-identifier heads, which mirrors the split between interning and resolution in Clang~\cite{clangident}. All tables implement the same operations with the same semantics, and names are passed as existing string objects.

\subsection{Measurements}
Each table and trace gets four passes. (i) Every result is compared with a reference model built on \code{std::map}. (ii) Heap is measured through an allocator hook using \code{malloc\_usable\_size}; a \code{realloc} that moves a block is charged for both blocks. (iii) The whole trace is replayed 15 times after two warm-up replays, with one timer per replay; we report the median and a 95\% bootstrap interval. (iv) Per-call latency is taken with the time-stamp counter, with the measured cost of an empty interval (\TimerNs\,ns) subtracted; these values are near the method's resolution and are secondary. For fixed mode we find by bisection the smallest buffer that replays a trace without a refused operation. Runs were pinned to one core of an Intel Core Ultra 7 258V under Linux (WSL~2), GCC 11.4, \code{-O2}.

\subsection{Correctness}
\st{} passes its unit tests under AddressSanitizer and UndefinedBehaviorSanitizer, including randomised sequences against the reference model, fixed-buffer exhaustion, and an allocator that fails after $k$ calls. In the benchmark, \PairsOk{} of \PairsAll{} table--trace pairs on the compiler traces had no wrong or refused result.

\subsection{Options and stress cases}
Name packing reduces the minimum buffer by \PackMin--\PackMax\% and is slower on \PackSlowN{} of \NTraces{} traces (by up to \PackSlowMax\%). Limiting the index to half full instead of three quarters lowers replay time by a median of \SparseGainMed\% and enlarges the minimum buffer by \SparseMemMin--\SparseMemMax\%. On a synthetic trace that enters a 10{,}000-declaration scope 20 times, \st{} is slower than METIS-X (\BigStrata{} against \BigMetis\,ns per operation) because it returns the buffer after each scope and regrows it; with shrinking disabled it takes \BigNoShrink\,ns. With every key forced into one probe cluster, a lookup among 4{,}096 names takes \WcHit\,ns instead of \WcHitNormal\,ns: the table has no defence against adversarial keys. On the four heuristic traces of the earlier study, kept as a supplement, peak heap is \LegacyHeapMin--\LegacyHeapMax\% and replay time \LegacyTimeMin--\LegacyTimeMax\% below METIS-X.

\section{Related Work}
\label{sec:related}
The algorithm of \st{}, a single hash table with an auxiliary stack that is unwound at scope exit, is described in compiler textbooks~\cite{appel1998,aho2006} and implemented in LLVM's \code{ScopedHashTable}~\cite{llvmsht}. Clang separates an identifier table from a resolver that chains declarations per identifier~\cite{clangident}; TCC keeps a per-token symbol pointer and pops symbol stacks~\cite{tcc}. Fingerprints stored beside the key follow Swiss tables~\cite{swisstables}. Deletion in linear probing normally needs tombstones or shifting~\cite{knuth3,bender2021}; last-in first-out deletion needs neither, which follows directly from the insertion rule. Character packing goes back to RADIX-50~\cite{radix50}, and stack-like allocation by lifetime to arena allocators in compilers~\cite{hanson1990}. Relative to these, the specific points of this work are the single caller-supplied buffer with a defined failure result, the compiler-generated traces, and the measurements. Our search of prior work was not systematic.

\section{Limitations}
\st{} was not integrated into a compiler; replaying TCC's calls measures the table, not a compilation, and symbol tables are a small part of compile time and memory. Nothing was run on a microcontroller. The traces reflect one compiler and C only. Timings come from one laptop under a hypervisor and vary between runs. Four of the baselines were written by us after known designs and are not the production code of LLVM or Clang. The exception-safety defect of METIS-X was found by inspection, not triggered.

\section{Conclusion}
Rebuilding the table around the identifier instead of the declaration removed the defects found in METIS-X and gave the lowest memory of ten tables on compiler-generated traces, with a fixed-buffer mode whose required size we can state per project. It did not give faster lookups, it made scope exit slower, and a simpler interning table is faster when memory is not constrained. The next steps are to replace TCC's own tables with \st{} and measure compilation, and to run the fixed-buffer mode on a microcontroller.
