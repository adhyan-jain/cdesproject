# Addendum of 2026-10-17: corrections and refinements to earlier documents

The theory manuscript in `theory/` and the adversarial review in `review/` changed five statements
made elsewhere in this repository. Nothing in `include/`, `tests/`, `benchmarks/` or the
raw results was changed; the earlier documents are left as written and are corrected here.
Every number below is produced by `bash theory/verify/run_all.sh` (tables in
`theory/paper/tables/`).

## 1. The probe-limit bound is valid but much looser than stated

Affected: `docs/PROBE_LIMIT_ANALYSIS.md` (section 2), `paper/body.tex` (Section "Bounded Mode"),
README (row "Probe limit").

* Statement made: the Chernoff-type bound `rho^L / (1 - rho)` is "loose by about two orders of magnitude".
* Corrected: the exact refusal probability is known in closed form (manuscript Theorem 7, the exact refusal law). At load 3/4
  and 65 536 slots the bound exceeds the exact value by a factor 315 at L = 64, 668 at L = 128,
  1 611 at L = 256 and 4 637 at L = 512; the factor grows like `L^{3/2}`.
* Consequence for the recommended limit: the smallest L with refusal probability at most 1e-6 per
  declaration at load 3/4 is **258** for large indexes (the bound demands 455). It is smaller for
  small indexes (121 for 256 slots, 201 for 1 024 slots, 242 for 4 096 slots; manuscript Table 1).
  The recommendation "512" in the README is therefore safe but conservative: at 65 536 slots it
  corresponds to a refusal probability of 2.4e-11 per declaration, not 1.1e-7. The library default
  is unchanged (the probe limit is opt-in).
* Validation: the exact law matches exhaustive enumeration in exact arithmetic (258 cases) and the
  real `strata::Table` in 7 settings of 400 000 trials (largest |z| = 1.96).

## 2. The memory saving is a hash word plus packing, not interning

Affected: `NOVELTY_GATE.md` section 8 ("competing explanation for the memory saving ... not built"),
`paper/body.tex` ("The saving is nearly constant ... no stored hash, no chain link, a packed name, and
one undo word"), README row "Memory against a conventional single-buffer table".

* Statement made: the compact design needs a buffer 16.4-17.9 % smaller than `arena_chain`; a
  conventional table without the stored hash "was not built".
* Corrected: two word-accounting layouts were evaluated (no hardware, no new code in the library):
  a chained table without the stored hash word and an open-addressed table with one entry per
  declaration. The accounting reproduces all 24 measured minimum buffers of the repository exactly
  (to 64 bytes), so it is trustworthy for the new layouts.
* Result on the eight traces: removing the stored hash from the baseline saves 9.2-12.2 %; packing
  names saves a further 5.3-9.0 % (relative to the hash-free layout); interning with the undo log
  changes the footprint by between 0.00 % and -0.38 % (it is slightly *larger*, because a scope mark
  costs two words, not one). The honest statement is "against a conventional table that stores a
  hash and unpacked names, STRATA's buffer is 16-18 % smaller; against one that does not store the
  hash, it is 5-9 % smaller, all of it from name packing".

## 3. "223x" in `reports/NOVELTY_ASSESSMENT.md`

The flooding slowdown at 32 768 names is **about 300x** (1 954 ms against 6.5 ms;
`results/hardening/flood.csv`), as in the paper and README. The "223x" in the audit text is from
an earlier run and is superseded.

## 4. "With a keyed hash, Proposition 2 applies to adversarial input"

Affected: `paper/body.tex` (Section "Keyed Hash"), `docs/PROBE_LIMIT_ANALYSIS.md` ("What the bound needs").

Correct only if each table is created with a key that is independent of everything the adversary has
seen (manuscript Proposition 11, fresh key). With one persistent key and a probe-length oracle an adversary can
plant names that make the probe limit refuse honest names: 1-5.5 % of 700 honest names at m = 2 048,
L = 512 (5 seeds, `theory/verify/adaptive_key_demo.out`), 0 % against a freshly keyed table. The
library does not need to change: derive a new key per translation unit from a device secret and a
never-repeating counter. The work bound (at most L index slots per call) holds regardless of the key.

## 5. Scope-exit and interning descriptions

README and the paper describe the interned layout as the source of STRATA's compactness. Section 2
above shows this is not supported by the traces: the interned layout is space-neutral for programs
that shadow little. The ledger identity (manuscript Proposition 14, the ledger) states when it pays: the saving is
`sum over hidden declarations of ceil(len/4)` words minus one word per open scope.
